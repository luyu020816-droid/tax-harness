# 冻结知识检索评测 v1

2026-10-30，第一批的合成制度评测。标注由实现者编写，不冒称外部数据、独立评委标注或人工验收。主办方材料与原40例未改动。

- development.json：12个制度主题，24个可回答问题、12个无答案问题。
- holdout.json：24个不同制度主题，48个知识问题、12个无答案问题、10个权限/版本/预算探针。含4份实际生成并解析的DOCX表格；其他为Markdown。
- 制度主题作为家族，开发与留出不共享主题或同一事实的问法；两份题库内部可以包含同义问法。公共版式、流程记录模板是相同的，结果只说明这个合成制度域的表现，不能外推真实企业全部资料。
- `units`为完整金标准原文。每个知识问题必须同时找到A主条款和B例外，C为流程背景，D为无关说明。`grades`提供0—3等级，chunk继承其包含block的最高等级。完全没有标记的标题块为0；不把只命中任意一条算完整回答。
- 8个留出主题、4个开发主题有较长的流程背景，使主句与例外实际跨chunk。评测用真实tokenizer与解析结果验证，并报告实际跨chunk数量。

## 测量协议

1. 冻结JSON及本文后运行开发集，拟合logit选择阈值；策略绑定开发集hash、实际profile和selection版本。
2. 锁定策略hash再运行留出。留出结果不反馈到本版阈值选择。若失败，保留失败并明确下一版需新的独立留出，不能删题补成绩。
3. 查询通道：词法30、向量30、单层RRF前20、同一候选池真实重排。记录Recall@20、nDCG@10，另测旧top6选择回放、仅按校准阈值选片段和完整证据组选取。
4. Recall按所需金标准单元的覆盖计算。nDCG使用(2^grade-1)/log2(rank+1)。不确定性用以制度家族为单位的配对bootstrap，默认2000次，不能把同一制度的两问当独立样本夸大把握。
5. 负例的“检索仍返回片段”与“最终模型错误作答”分开。前者不等于已经发生错误回答，后者需真实DeepSeek工具与AnswerPlan验证。原文不支持答案时仍须knowledge_insufficient。
6. 真实查询向量与重排结果可按输入和profile精确缓存，记录来源hash；基线推理耗时与缓存后重放耗时分开，不将重放延迟称为生产延迟。
7. 语料在独立、每次新建的评测数据库中通过实际上传/解析/索引路径建立。文件创建时间设为合成的历史日期，表示跨多日形成的语料，避免将批量装载变成每小时20次上传的测试；线上配额实现不变，配额另有程序反例。未清空生产库、原测试库或用户资料。

本批70个留出项不包含计划中的历史30题；完整100题需在历史语义模块完成后联合验收。自动hash/定位校验不是语义支持度人工签收。

`fixtures.py`只用于从已写好的条款生成冻结JSON。测试和评分只读取提交的JSON；运行评测不会根据结果改写fixture。
