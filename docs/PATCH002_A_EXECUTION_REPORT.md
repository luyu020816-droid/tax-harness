## 推理诊断

`scripts/verify_native_inference.py` 使用真实 BGE 模型，不用向量/重排缓存；一旦发生重启即使重试成功也失败。6 轮短候选切换、12 轮 20 候选切换共 18 轮无重启；20 候选轮次约 16—19 秒，短候选首次冷启动约 99 秒，不能当作生产 SLA。

`.local/evidence/a1-concurrent` 为 4 个调用线程共 8 组真实向量/重排调用，结果长度正确，重启 0，约 64.95 秒。profile 仍为 `0892c00a8c75451a31c3f1be37bb51ce1c10814c1074188d2d789283b5824446`。

`.local/evidence/a1-agent-ready` 复验 8 个真实 Agent 场景，原生重启 0，自动检查 **7/8**；末页场景模型漏传 cursor，重新查了第一页。这不是 native 故障，作为已有日期导航的残余可靠性问题保留，不能写成 8/8。脚本现在在检查失败时返回非零退出码，并明确记录 native_restarts。

历史崩溃未复现，因此未进行没有因果证据的依赖升级或 mmap 参数变更。保留的后续假设及预测：

- 模型切换/权重生命周期问题：同进程反复切换应比不切换更易复现；本轮未观察到故障，尚不能确认。
- Windows 内存映射或提交压力问题：故障应随内存提交状态改变；本轮未在受控条件下证明。Hugging Face 有大模型 Windows mmap 崩溃的[上游报告](https://github.com/huggingface/transformers/issues/48285)，但模型规模与当前 BGE 不同，不能据此判定本项目根因。
- 原生线程状态问题：若仅跨调用线程才出现，应在固定工作线程消失；上一批固定线程后仍曾崩溃，不能把它单独当根因。

复现必须同时记录相同输入、依赖/profile、模型切换、内存状态和退出堆栈，得到可重复失败后才能验证根因修复。没有以当前零故障样本关闭这项缺陷。
