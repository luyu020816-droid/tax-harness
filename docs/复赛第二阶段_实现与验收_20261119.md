# 复赛第 4、5、7 项：实现与验收记录

日期：2026-11-19。分支：`feature_adjust_1117`。提交基线 `41124058a63e9d01c2096a3565baf151fc21cfbd` 加当前未提交改动。

需求依据为用户提供的《赛题二：财税+Agent+Harness+系统设计与实现复赛要求 (1).pdf》第 1—2 页。比赛要求描述可观察能力，不强制某个记忆框架、知识配置结构或压缩算法。本文记录实际实现和验证边界，不把开发测试当作主办方现场验收。

## 第 4 项：长期记忆

现有权威数据库继续保存任务、明确偏好、来源与修订。个人偏好和企业范围偏好按当前用户、企业权限读取；新旧要求使用稳定键、来源顺序、期望 revision 和删除代次处理冲突。当前状态不依赖向量排名或模型摘要，不能由模型口头宣称保存成功。

本轮新增原入口「记忆管理 → 变更记录」：查看当前用户的记忆条目、有效/已删除状态，分页回看修订、删除代次及历史值；来源不可再访问时隐藏对应历史值。历史修订只在显式管理视图展示，不恢复为有效偏好、不参与自动召回。接口同时校验所有者及企业权限。

验证覆盖更正后新进程读取最新值、删除后当前上下文不再加载旧值、历史游标、跨用户拒绝。程序重启读取测试使用独立 Python 解释器连接同一隔离 PostgreSQL，未用内存缓存冒充持久化。已有恢复和记忆回归同时复跑。

边界：“失效”表示退出当前记忆及可用依据；显式审计视图仍保留修订，不宣称物理擦除全部原文、业务审计或备份。正式个人数据清除涉及独立保留政策，本轮未新增自动画像或无授权记忆抽取。

## 第 5 项：知识库策略

保留原有资料新增、解析、发布、换版、停用、混合召回、重排、完整条款组、引用原文和版本校验。资料有效性、个人/企业权限及 Agent 的知识范围继续作为强制交集，不因策略设置扩大。

新增企业级、可持久化的检索策略及不可变历史版本：检索启停、重排开关、是否只接受已校准结果、证据估算预算、完整条款组上限。原入口「知识资料 → 知识库检索策略」支持查看、编辑、发布、重新载入和载入历史配置后发布为新版本。发布须满足本机同源、配置管理授权和当前企业访问权；过期 revision 拒绝覆盖。

每次检索记录实际策略版本。策略发布推进企业知识代次；旧检索和旧引用失效，运行中的旧结果不能继续作为依据。严格校准模式在重排/校准条件不足时不给出可用证据；策略版本缺失时明确不可用，不静默采用默认配置。较小预算按完整条款组选择，遗漏标为覆盖不完整。

本地真实组件另用两份模拟资料和三条改写问法验证：住店报销审批、紧急出行审批、未批准酒店开销，三条均命中目标资料。使用真实本地 embedding 与重排、真实 PostgreSQL 向量索引；profile 为 `0892c00a8c75451a31c3f1be37bb51ce1c10814c1074188d2d789283b5824446`。这是三例组件验证，不是任意问法召回率或完整语义质量保证。

## 第 7 项：上下文管理

延续完整请求预算、输出预留与误差余量、关键任务/偏好常驻、闭合工具组、近期对话保留、分批压缩、失败保留旧视图与原文回读。

本轮补齐 Agent 场景：

- 下一次输入预估计入当前草稿、所选 Agent 提示词、Skill 指引及授权工具，并按其模型配置计算预算。界面分别标注最近实际用量与下次估算，不把估算伪装成服务商实际 Token。
- 原助手和 Agent 均可使用 `/compact`。控制请求绑定 Agent/配置和模型版本，保留权限与幂等检查，不作为普通聊天或业务写授权。前端重试身份区分所选 Agent。
- 摘要按用户、会话、企业、Agent 发布配置及企业知识代次隔离；受限 Agent 不加载范围外历史，其他 Agent 不复用其摘要。知识范围变化后旧摘要不继续使用。原文回读也使用同一摘要范围校验，不能通过猜来源 ID 绕过。
- 压缩发布与发送前再次检查作用域、来源及当前授权；失败不覆盖旧摘要、不删除原始消息。没有可压缩的较早对话时返回真实无内容回执。

预估仍是 UTF-8 启发式，明确未计入受理后才生成的范围引用、附件元数据、后续工具结果等动态项；发送时仍以执行器重新装配和预算检查为准。压缩保护关键状态和原文锚点，不承诺摘要语义无损。
