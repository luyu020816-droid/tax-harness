# 第二批：历史语义检索与日期查找

日期2026-10-30，接续已批准SPEC第10.5节、H01—H04和路线图第5步。用户明确要求继续下一批；本文件细化执行，不新增业务能力或重新申请既有范围的批准。

## 边界与选择

沿用Source作为原文真值，正式任务/显式偏好仍精确读取。选择“数据库派生passages＋同一真实BGE/RRF/重排”，不用向量替代正式状态，也不另建外部向量服务。纯日期浏览直接读取Source，向量不完整时仍可用。历史原话绝不成为新业务授权。

历史使用独立查询/引用表，因为Source修订、消息发生时间和个人私有范围与知识文档版本不同；外部仍共用corpus QueryPlan、EvidenceBundle及/evidence入口。复用真实模型、分词、RRF、持久作业的租约/fencing模式和来源有效性检查。知识域阈值不能未经验证套到历史域。

## 顺序与验收

1. 新增非向量权威迁移和可选向量迁移；Source与待处理任务同事务。旧Source显式回填，不改其内容/时间/修订，不重导Excel。新增表自动纳入全表备份指纹。
2. 作业在锁外分块/真实推理，发布前核验Source状态、revision/hash及租约；过期执行不能发布。向量服务失败只影响派生索引，正式任务/偏好和已保存原文保留。回填/重试幂等。
3. 历史查找先核用户、企业、当前Source修订与读取水位，再做词法/向量候选和真实重排。返回角色、消息日期、字符定位、hash、持久citation及覆盖缺口。未校准/降级明确partial，不以无向量命中声称从未说过。来源携带检索结果的工具输出不再次语义索引，避免递归复制；其原文仍保留。
4. 日期浏览无需query/entity，双端日期窗口至多31天，按Source顺序每页最多5条，游标绑定范围/身份/水位。过大原文明确摘录范围与分页/预算，不静默把片段当全消息。
5. 工具、HTTP、上下文和宿主引用共用该实现。只能引用真正入模的摘录，回读重验权限、revision及抑制状态；历史助手“已保存”标注为历史文字，不能渲染当前保存成功。更正/删除后，即使旧向量保留也不得回读、再次入模或发布旧引用。
6. 独立程序反例先失败后实现；分开的历史开发集与30项留出，用至少30天前、跨会话的合成消息和真实BGE验证。报告召回、角色/定位、无答案、删除/撤权/读取水位、日期分页与真实Agent表现。已知失败保留，不改原40例断言。
7. 相关及完整回归、原业务真实模型回归、预览迁移前备份和安全重启，更新契约/报告/路线图；本批不做OCR或完整长上下文/故障矩阵，不推送远端。

## 本批成功条件

H01有真实同义召回证据；H02在向量不可用时仍能日期分页；H03旧向量和旧引用不能复活被更正/删除的偏好；H04助手历史只作原文、当前业务重新查询。跨用户/企业泄露为0，迟到任务不发布，正式任务和偏好不因历史索引进度被替换。可定义测试边界，不能承诺任意自然语言零遗漏或单机介质损毁后零丢失。
