## 2. 机制变化

| 位置 | 本批行为 |
|---|---|
| 候选检索 | 沿用真实jieba/PostgreSQL全文、BGE-M3/pgvector、单层RRF与真实BGE重排；保存通道排名、分数与阶段耗时 |
| 相关性选择 | 从独立开发集选择raw reranker logit阈值；绑定profile、开发集hash和算法版本；不把分数解释为正确概率 |
| 必要证据 | 依据已保存标题、条款、续文及表格建立结构组；同组主句、例外、否定条件和表头共同选取；按来源/版本保留，不跨文档只按文本hash合并 |
| 预算 | 最多6组、总计3000个UTF-8字节数/2保守估算tokens；整组放不下则省略整组并返回partial，不能截掉例外继续称完整 |
| 回源 | 持久citation继续核验当前权限、当前版本、hash及epoch；read_evidence新增related_evidence返回同组其他片段 |
| 最终展示 | 即使模型只选择主句citation，宿主仍验证并展示同组全部已入模引用；缺少入模成员则拒绝交付并要求重读，不偷偷补充模型没看过的正文 |
| 降级 | 策略缺失/不匹配明确未校准；词法或未重排模式不套用hybrid阈值；依赖故障不冒充知识不存在 |

结构组只保证明确结构关联：Markdown低层标题、显式例外/附注、编号条款和解析表格。对无明确边界的文本保守扩大组，可能因预算拒绝。没有实现任意跨章节隐含语义关系识别。旧M3引用没有历史组元数据时保持单条可读，需重新检索才能获得新组，不能伪造旧关联。

实体约束用于词法和向量的候选过滤。结构组扩展保留必要上下文，不能将同一条款中的其他编号自动解释成用户本次操作目标。业务修改仍由精确票号、列表身份和授权计划控制。
