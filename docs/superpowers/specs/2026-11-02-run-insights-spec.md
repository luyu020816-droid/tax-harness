## 1. 目标与成功标准

将现有「运行记录」升级为一个「运行洞察」Tab。围绕用户请求关联所有执行、模型尝试、工具结果与保存回执，回答：为什么慢、费用来自哪里、依据是否有效、事项是否交付、失败如何恢复、优化是否有效。

本轮完整范围包含：可靠采集、历史聚合、单次轨迹、记忆与业务证据、只读评测对比、权限脱敏及人工验收。按第 12 节六批实施；完成前三批只能称“基础观测可用”，不能宣布整个 spec 完成。

成功标准：

- 同一消息失败后恢复仍归入同一请求，能看到所有执行和费用，不重复计数。
- 任一指标可下钻至组成该指标的请求、尝试和证据；缺失数据可定位。
- 能区分模型等待、工具耗时、排队、上下文组装和宿主处理；不能确定的部分直接标注未知。
- 能查看实际入模的来源、规则与当前有效性，查看保存授权、提交和核验的关联。
- 请求、模型、工具三个层次的完成状态分别展示；自动检查不冒充人工正确性签收。
- 页面保持 Orbit 风格，默认信息密度适中，360px 到桌面均可操作。

## 4. 领域对象与数据模型

### 4.1 关联层级

`session → turn（用户请求）→ run（执行代次）→ span（阶段/调用尝试）`。

- `turn_id` 是请求主键；`client_request_id` 重试不增加请求数；不能将新用户消息仅凭文字相同合并。
- 恢复产生新 run，沿用原 turn；原有 `continuation_of_turn_id` 作为消息关联显示，不擅自合并统计。
- 模型一次实际发送对应一个 attempt span；摘要、纠错、自动重试都分别计量。控制确认快照不是模型调用。
- 工具幂等命中允许出现“读取已有结果”span，但不增加实际保存笔数。
- 保存与偏好回执引用原账本，观测模块不复制一套“成功”事实。

### 4.2 最小增量存储

新增下一顺序迁移（当前为 010），允许新增两张表和一个 run 快照字段，不引入第二套会话事件总线：

**`trace_spans`**：`span_id`、`run_id`、`parent_span_id?`、`logical_key`、`kind`、`name`、`status`、`started_at`、`ended_at?`、`duration_ms?`、`measurement_kind`、`context_id?`、`tool_call_id?`、`error_code?`、`attributes`。

- 唯一键 `(run_id, logical_key)` 防重复采集；父子节点须属于同一 run。属性按 kind 白名单校验，不接受任意大 JSON。
- `kind` 限定为 `context / model / tool / retrieval / write_verify / host`；`status` 为 `running / succeeded / failed / cancelled / interrupted / not_dispatched`。
- 时间区间使用 UTC；同一进程持续时间用单调时钟测量。未知保持 NULL，禁止负数或补零。
- `measurement_kind` 为 `measured / event_derived / estimated / unknown`。历史投影不伪装成新实测。
- model 属性记录 `attempt_kind`（normal/summary/repair）、`request_dispatched`、model/provider 标识、输入哈希、usage 原字段、usage 状态及价格版本引用。不得写入 Key、Cookie、Authorization 或连接串。
- tool/retrieval 属性只存必要计量和已有证据 ID。完整参数、来源与结果通过受控详情读取，不在多个 span 中重复复制。
- phase 起止须包住所命名的实际工作；检索模型加载、检索和重排的细分仅在采集到时生成子 span。

**`runs.insight_snapshot`**：版本化 JSON，保存采集协议版本、代码指纹、模型与参数的非敏感配置、上下文/检索策略 ID、数据集标识和可用的数据/规则版本。缺失的旧版本字段标 unknown，不用当前配置补造。

**`insight_evaluations`**：可信本地报告导入后的 ID、owner、企业范围、代码/数据/策略/价格指纹、报告哈希、样本类型、样本结果、人工签收状态和导入时间。报告只存指标、断言与受控引用，不导入私人完整 Prompt。

价格采用版本化受控 JSON 配置；模型精确匹配，不隐式推断别名。不再增加价格服务或计费系统。数据库角色按既有模式最小授权，运行角色不能通过观测表修改业务。

### 4.3 权威与历史兼容

- 业务、回执和来源数据库是事实；span 是观测，聚合是派生；三者矛盾时展示差异，不覆盖原账本。
- 历史记录先从原始字段和已配对事件进行投影，保留 origin；不强制修改旧表行，不自动扫全库回填。
- 工具按 `(run_id, tool_call_id)` 配对，模型按 context_id 配对，不按最近时间猜关联。
- 无结束事件保留 incomplete；程序重启后可标“中断/结束时间未知”，不能将最后一条日志时间当作精确结束。

## 5. 计量口径

### 5.1 时间

| 指标 | 规定 |
|---|---|
| 请求完成历时 | turn.created_at 到明确终态事件；跨恢复包含停顿与用户等待，单独列出，不当作纯处理时延 |
| 首次排队 | 首次 run.started_at 减 turn.created_at；恢复排队以 recovery_queued 事件为起点，缺事件则未知 |
| 单次执行历时 | run 的开始到结束；运行中显示“已运行”，不进入完成耗时分位数 |
| 活跃执行时间 | 各 run 的执行区间并集，不把重试间隔算活跃执行；区间不全时只展示已知部分 |
| 模型耗时 | 从实际 HTTP 尝试开始到完成/异常，包含网络；不能直接称作供应商推理时间 |
| 工具耗时 | 实际工具执行包围区间；SQL、校验、回读等细分只在对应子 span 有测量时展示 |
| 节点总耗时/独占耗时 | 父节点覆盖子节点，不再次累加到请求总耗时；独占耗时扣子区间并集，覆盖不全则不计算 |

时序图按实际开始/结束定位，串行和并发按真实区间显示。不具备依赖证据时只标最长已测阶段，不声称找到了精确关键路径。余量标“未细分宿主/间隔”，不自动归因为数据库慢。

P50/P95 对同一筛选集、已终结且完整计时的请求活跃执行时间计算 nearest-rank（`ceil(p*n)`，从 1 起）；显示有效 n、排除数，n=0 返回 null，n<20 提示“小样本”。完整处理历时在详情另列。失败请求如有完整计时须纳入耗时分布，并允许按状态分组。

### 5.2 状态、成功与正确性

- 请求数按 distinct turn；执行数按 distinct run；实际模型尝试按 dispatched model span，三者不得混写。
- 顶部使用“完成比例”，定义 `completed / 已终结请求数`；已终结包括 completed、waiting_user、failed、cancelled、interrupted。运行中/排队单列；等待补充不标为系统故障。
- 技术成功、等待补充、取消、中断、工具错误分别展示。取消不归入模型接口故障率。
- 正确率仅来自有冻结预期或人工签收的评测；线上无标签请求显示“未评估”，不能用 completed 代替正确。
- 业务事项标 `已交付 / 已执行待交付 / 待补充 / 未执行 / 未核验`，同时标来源：用户明确项、模型识别、冻结测试预期或人工标注。模型清单不作为独立正确性证明。

### 5.3 Token 与费用

- 实际用量以 provider usage 为准，分别累计 prompt/completion；缓存命中是输入子集，reasoning 等细分也是相应总数子集，不重复相加。
- 控制确认、纯数据库操作和未发出请求不算模型调用。请求已发出但响应丢失时 usage_unknown；不能据网络失败断言免费。
- 输入构成按 system、工具定义、正式状态、近期历史、摘要、检索、工具结果分类；标注字符/UTF-8 预算估算方法。分类不得重叠，协议未归属部分单列；模块估算不伪装成供应商计费拆分。
- 费用按实际 usage 与匹配的价格快照，用 Decimal 计算；包含所有摘要、失败、纠错和恢复尝试。
- 有缓存拆分按 hit/miss 计价；无拆分但总量有效时给出“全未命中上界估算”，与普通估算分开。
- 输出 `known_cost / complete_cost? / unknown_calls / pricing_version / currency`；任一收费尝试未知，完整费用为 null。不同币种不直接相加，缺价格或模型不匹配保持未知。
- 不沿用 2026-10-31 的价格作为“当前实付”。默认页面显示匹配快照的归一化估算，并注明不含本地计算和存储成本。

### 5.4 采集覆盖率

分别显示 actual usage 覆盖率、完整耗时覆盖率、配置版本覆盖率和未闭合节点数。分母说明清楚：usage 分母为已发出模型尝试；控制快照不进入分母。未知不记零、不从列表隐藏、不补造漂亮曲线。

## 6. 采集与业务隔离

1. 模型调用通过一个公共计量包装器覆盖普通、摘要和修复路径，保留原适配器协议。开始先标 dispatched，finally 记录耗时、错误和已知 usage；不额外发起模型请求。
2. 每次尝试唯一关联 context。已收到响应后因 epoch 守卫拒绝发布，业务仍拒绝发布；非敏感计量应独立保留，不借此提交旧摘要或来源。
3. 工具外层与内部明确阶段按需采集，避免保存和回读重复计算；原有审计与事务协议保持不变。
4. 审计必需记录继续遵守既有强一致协议；新增计量在短事务中记录，写失败不改变已经提交的业务结果。运行日志记录脱敏采集错误，未闭合计量显示缺失。
5. 未观测到的网络发送边界、崩溃或计量落库失败不能保证零丢失；原始开始/结束事件与 span 不一致时暴露缺口。
6. 读接口不加载 BGE/OCR、不执行重排、不调用模型、不重新检查业务、不激活规则，也不为了填图重新运行工具。

## 7. 记忆、规则与业务证据投影

详情提供以下证据，字段缺失标“历史未采集”：

- 记忆：来源类型、source_id/revision、scope、epoch、入模位置、选择原因及被排除的明确原因。展示当时快照与现在有效性，不用当前值覆盖历史。
- 检索：query_id、模式、候选计数、实际保留的候选/分数/策略 ID、最终证据和引用。历史未保存完整候选时不重新检索补造。
- 摘要：摘要 ID、覆盖来源、受保护摘录数量、预算、生成结果/失败原因；可核对合法原文。不能据来源覆盖判语义无损。
- 规则：实际使用版本、企业、生效范围及当前状态；已停用版本可显示为历史依据，不可当作当前有效规则。
- 保存：授权来源 → 企业/票据 → expected_revision → operation_id → commit/verification 状态 → 实际回读 → 交付卡片。偏好修改使用自己的回执类型。
- 恢复：旧 run、新 run、接管/排队事件、恢复前核对结果、实际操作笔数、revision 变化与旧 token 拒绝证据。没有证据时不显示“去重已证明”。

“命中→入模→引用”可程序判定；“模型是否正确理解/用户全部需求是否覆盖”只能展示既有验收结果或标未核验。摘要反例修复、业务规划修复另立工作，不在投影层偷偷改变运行逻辑。

## 8. 读接口契约

新增接口位于 `/api/v1/insights`，沿用 cookie 身份：

| 接口 | 作用与边界 |
|---|---|
| `GET /summary` | 同筛选范围的全量聚合、各指标分母/覆盖率、as_of、是否截断；不只聚合列表当前页或旧接口前 100 条 |
| `GET /requests` | 请求级摘要列表，默认 20/max 50，游标分页；无完整 payload |
| `GET /requests/{turn_id}` | 请求、各执行摘要、最小轨迹与计量；节点详情懒加载 |
| `GET /runs/{run_id}` | 原聊天详情入口映射至所属请求；仍检查请求完整企业范围 |
| `GET /runs/{run_id}/spans` | 单执行节点分页，每页100项；不加载完整原始输入 |
| `GET /spans/{span_id}` | 经统一权限与来源检查后的单节点输入、输出、证据；支持原始数据分页 |
| `GET /requests/{turn_id}/export` | 同权限的脱敏 JSON；只导出已提交数据，不运行或恢复任务 |
| `GET /evaluations` | 可见的已导入评测摘要列表 |
| `GET /evaluations/{evaluation_id}` | 固定样本逐项指标、失败与证据关联 |

summary/requests 共用参数：`from`、`to`（带时区、半开区间）、`company_id?`、`status?`、`model?`。默认上海时区最近 7 个自然日含当天，支持最近 30 日或自定义最多 31 天。按 turn.created_at 选择请求，包含其全部执行（即使恢复跨过筛选终点）；响应注明范围语义和 as_of。model 筛选表示请求曾使用该模型，返回请求内全部模型的执行和费用，不静默截掉其他模型；混合模型标记可见，不据此计算单模型因果收益。

列表排序固定为 `(created_at DESC, turn_id DESC)`；“仅慢请求/最贵”等排序作为后续扩展，不允许本地重排当前页冒充全量排行。本轮用筛选和详情定位。游标绑定用户、筛选与 as_of（请求受理高水位），keyset 翻页不重复；过滤变化重置。as_of 不冻结后续执行状态或当前授权，运行中状态变化、撤权会使集合变化；页面提示实时变化并提供刷新重置，不宣称跨页为不可变审计快照。历史权限每次请求重新校验，游标不能缓存旧授权。

默认响应含 `schema_version`、`as_of`、`measured_at`、`coverage`；每个数值带单位和 measurement_kind。聚合/列表复用同一可见性查询；一次 summary 在同一个只读 REPEATABLE READ 事务中完成全部分子分母。不同 measured_at 的实时列表与聚合可能变化，不能假称为同一快照；需要固定比较时使用冻结评测报告。查询超时返回明确错误，不返回 0 冒充无记录。

原 `/runs`、`/runs/{id}` 与 export 保留协议入口供旧页面使用，但共享脱敏与访问检查。原始字段被限制时以结构化 `redacted/reason` 替代，不直接泄露或让详情组件崩溃。新旧入口权限不得有旁路。

## 9. 权限、隐私与只读边界

- 用户只看自己的请求。U001 能操作企业不等于能看 U002 对话，不增加全局管理员观测身份。
- 可见范围由服务端来源范围和依赖确定，不信任前端 company_id；一条请求涉及多企业时必须仍对所有涉及企业有权才展示。全企业视图按唯一 turn 计数，不把多企业请求重复相加。
- 无企业范围的私有请求只在本人未限定企业的视图显示；企业筛选不把私有内容强行关联。
- 撤权后的请求从列表、数量、趋势和导出全部排除；详情对不可见资源返回 404。无权企业筛选沿用 403。
- 更正/删除/抑制的原文、失效知识证据不通过历史 payload 或事件 message 继续展示。统一 serializer 验证依赖；某节点来源有效性无法证明时隐藏整个内容节点，保留可合法显示的计量和失效提示。
- 合法历史规则的旧版本与被删除的私有原文区别处理。访问观测不恢复记忆，不修改 source recall_state。
- 凭据在采集前排除，导出再脱敏；错误只保留类型、代码和允许的提示。原始用户内容不进入指标标签。
- 评测导入仅由持有既有本地管理配置的维护者执行 CLI，普通聊天和前端无导入/覆盖接口。报告绑定 owner/scope，不放宽真实轨迹访问权限。
- 所有查看、刷新、导出、评测对比不得改变发票、银行、偏好、任务、规则或队列状态。查询观测所需的读日志不算业务修改。

## 10. UI 与自然交互

### 10.1 入口与布局

现有 page id `runs` 保留，导航文案升级为「运行洞察」，不新增重复的一级导航；聊天内“办理记录”与 OrbitContext 入口跳到同一请求详情，返回后保留会话和草稿。

说明：查看任务轨迹、耗时与用量。     数据截至… / 刷新

                         采集完整度（可展开）
---------------------------------------------------------
历史请求列表                     选中请求 / 执行轨迹
时间 · 需求摘要                   状态 · 总历时 / 活跃时间
状态 · 耗时 · Token              执行 1
…                                  上下文 → 模型 → 工具 → 答复
上一页/下一页                    执行 2（恢复，若存在）
                                 节点证据按需展开

桌面内容区足够宽时双栏（列表约 32%，详情约 68%），详情最小宽 480px；不足时自动单栏，不能仅依据整个浏览器宽度忽视侧栏占用。侧栏、顶栏、用户/企业选择和全局错误沿用 App。

布局提供两种内容状态：历史轨迹；有评测报告时从页内“策略对比”按钮进入同一 Tab 的子视图，返回保留筛选，不再叠加多层 Tab。extended 的“数据导入”记录继续作为页内独立内容入口，不混入模型调用 KPI。

### 10.2 风格约束

- 复用 `styles.css`、`orbit-chat.css` 已有语义变量。Orbit 为深色蓝黑底、青紫强调；默认入口继续自有主题，不强制改成深色。
- 复用字体、Lucide 图标、圆角、4/8/12/16/24 间距、按钮、badge、表单、Modal/抽屉和错误样式。新 CSS 限于 insights 命名空间，禁止修改全局选择器影响聊天。
- 新页面以文字、低对比边框与轻量条形为主；五个顶部指标上限。首屏不堆仪表盘、环图、粒子、浮动动画或原始 JSON。
- 轨迹用垂直层级与横向耗时条；每个节点默认只显示名称、状态、耗时和模型 token。颜色结合文字/图标，不能只靠红绿区分。
- 状态强调沿用 success/warning/danger，明确失败可突出；“慢”不自动标红，显示数值和最长阶段提示，避免无依据阈值诊断。
- 展开层次为请求 → 执行 → 节点；普通节点默认折叠，失败节点首个自动展开一次，不随刷新抢焦点。原始 JSON 是末级折叠，超过 32KiB 按字节分块读取，显示总量与继续读取入口，不静默截断证据。

### 10.3 行为与响应式

- 时间、状态和模型使用中文标签；数字等宽，耗时默认秒且保留合理精度，token 千分位，费用显示币种和“估算”。NULL 显示未知/未采集，不能显示 0。
- 360/390/768px 单栏；选择记录进入详情，提供“返回历史记录”；侧栏可收起，过滤器可折叠，5 个指标自动换行。节点名称和需求摘要可换行，长 ID 可复制。
- 无记录明确范围；旧数据无 usage 提示历史未采集；加载骨架不清空现有列表；错误提供重试并保留筛选。
- 页面可见且选中运行中请求时，至多每 2 秒刷新一次；终结后停止。页面隐藏、切用户、切企业、离开页面立即取消请求与清空不再合法的数据。聚合默认手动刷新，避免每个节点独立轮询。
- 筛选以 URL 查询参数保留，白名单参数不含 Prompt、用户凭据或原文；刷新恢复所选合法 turn。通过 back/返回保持位置，键盘焦点可见，reduced-motion 下无非必要动画。
- 原始输入/输出与导出说明其隐私边界；无可用原文时显示失效原因，不渲染空白详情。

## 11. 评测对比与平台性能

### 11.1 对比报告

提供 CLI `scripts/import_insight_evaluation.py --file <report.json> --owner U001`：固定 schema 校验、报告哈希去重、owner/scope 验证；失败不导入部分报告，不覆盖旧报告，不接受任意远程 URL 或执行报告中的命令。

第一版仅支持仓库已有 advanced comparison 报告适配器与一种规范化 schema。展示开发集/留出/线上标签、数据/模型/代码/策略指纹、样本数、重复次数、正确/最终答对/摘要准备失败、P50/P95、token、费用及未知比例。缺少可比条件时并列展示，标“不可直接归因”，不给胜负结论。

逐样本可下钻冻结断言与失败，不把已见反例回归称新留出。真实向量、词法、缓存命中和模拟组件分开标注。不自动发起模型、工具或收费实验，不从已导入报告推断当前线上质量。

### 11.2 查询和采集开销

- 请求列表、聚合使用列投影和批量 SQL，禁止先读取每条完整 trace 再在前端汇总，避免 N+1；为 user/time、turn/run、run/parent 索引并保留 EXPLAIN 证据。
- 列表最多 50 项；轨迹节点每页 100 个；导出单次最多 10MiB UTF-8，超限返回明确错误，引导分 run/节点读取，不能悄悄截断。
- 无跨用户/权限快照共享缓存；本轮不依赖新增物化视图或后台指标作业。
- 保留本机独立测试库、10,000 请求且每请求 3 次模型尝试的基准，记录预热后串行30次的列表、聚合和首屏详情 P50/P95、环境与样本量。此前500ms/1000ms目标只作非阻塞参考，不因1.43秒等可用响应单独判失败。无新故障或明显体验退化时不重复跑基准、追求更低数字。
- 可用性验收：当前数据规模下页面和详情可打开，有明确加载、错误与重试反馈；筛选、分页、展开和返回正常；统计不影响业务状态，不使业务明显停滞。已有查询超时、分页与大小上限继续作为资源保护，不宣传响应 SLA。
- 采集开/关的无模型业务回放记录额外事务和延迟；此前100ms只作参考。若出现业务阻塞、超时或明显退化，再定位问题，不能删审计换速度。开关只控制新增可选计量，不关闭业务审计和安全守卫。
