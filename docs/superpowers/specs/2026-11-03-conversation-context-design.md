## 1. 决策与范围

取消“固定选择最近12轮”作为默认上下文策略，改为：**追加式会话日志 → 根据权限构造当前有效上下文 → 按输入预算压缩较早的完整段 → 保留可定位原文 → 按需检索历史**。

继续使用 PostgreSQL、Python Runtime、现有模型适配器和财税工具。借鉴 DeepSeek Harness 的会话语义，不移植其整套插件系统，不把数据库替换为JSONL，也不把所有业务表改造成事件溯源系统。

三种信息边界：

| 信息 | 内容 | 查找与使用 |
|---|---|---|
| 聊天历史 | 用户消息、助手回答、工具调用及结果的历史证据 | 独立历史查询，标明角色、会话、时间；不是当前授权 |
| 知识库 | 比赛规则及用户手动提交的制度、文件、文字 | 文档检索、版本和引用；可执行规则仍经受控维护生效 |
| 当前业务状态 | 发票、银行、有效任务、明确偏好、当前规则版本 | 读取当前数据和账本；不以旧聊天数字或旧回执代替 |

业务规则属于知识库的业务知识；规则执行条件可以使用专门的版本表和确定性程序实现，产品概念不因此拆成另一套知识库。

偏好候选、用户确认和误判评测继续作为独立TODO，本方案不实施周期性用户画像提取、不把隐式行为自动升级为正式偏好。

## 2. 已核对的现状与问题

| 位置 | 现状 | 后果 |
|---|---|---|

DSH允许在一轮内部的已闭合工具区间切分，自动压缩失败的路径会警告后继续；这不代表后续模型请求必定成功。我们的财税交付不能以失败后的静默丢消息来凑预算，选择“保留旧投影；装不下则暂停”的适配。DSH恢复中区分工具未开始与结果未知，对应我们现有operations回查，不因恢复日志缺少结果就重放保存。其默认额外余量65536 Token不适用于本项目16k输入预算，采用本项目预算计算和实测校准。

## 5. 日志与当前状态如何共存

新增一个逻辑会话事件序列，建议表名 `conversation_events`。事件有：session_id、session_event_seq、user_id、turn_id、run_id/generation、event_kind、source_id或受控payload、内容hash、created_at、origin/provenance。会话内顺序由事务分配，不以时间戳排序代替；唯一约束包含会话序号和幂等来源键。

用户/助手正文继续以既有sources原文为依据，事件引用source_id和hash，避免复制两套可各自修改的正文。工具调用参数没有现成来源时在事件中记录受控参数，结果引用工具来源。请求头/完整模型输入继续由context_snapshots持有，事件关联其ID，不重复记录凭据或内部推理内容。

首批事件范围：user_message、tool_call、tool_result、assistant_final、turn_end、compaction_published、conversation_deleted。未通过交付校验的候选回复属于执行审计，不冒充已展示的助手答案；跨run的不同尝试明确区分。工具错误、取消与结果未知均保留真实状态，不补造成功结果。

原文内容和事件payload对普通应用角色禁止UPDATE/DELETE；sources的可召回状态、范围元数据等按既有需要受控更新。数据库约束或触发器保护正文；同时收紧初始化和升级脚本授权，避免普通启动重新授予整表UPDATE。管理员恢复/迁移单独授权、校验和留记录；不声称防御数据库超级管理员。

`turns`、会话组织字段、任务和偏好保留可更新的当前状态。它们不是完整业务事件重放系统；不承诺仅凭新会话日志重建全部财税业务库。

新消息受理时，轮次、原文、会话事件和排队工作同事务提交。工具调用先登记调用事件，再执行副作用；结果入账与结果事件事务绑定。业务提交后回包丢失仍先查operations账本，再追加核验结果，不从“缺工具结果事件”推断“未保存”。

## 6. 新上下文策略：取消固定轮数

新增 `conversation_projection.py`，其主要接口为 `project(execution, budget)`，返回模型消息、来源manifest、摘要覆盖水位、需压缩的完整前缀、缺口/不可用状态和估算用量。Runtime不再自己决定取最后N轮。

读取时固定snapshot上界：当前turn的会话事件位置、执行generation、授权/组织revision和适用memory_epoch。只考虑上界之前的有效记录，防止并发新消息、当前工具结果重复、恢复旧run混入本次历史。

从有效摘要水位之后按游标分批读取并构造完整对话组。数据库分页大小仅控制I/O，**不是模型记忆轮数上限**。预算充足且无摘要时，当前会话的所有适用历史都可进入投影；已有有效摘要时使用摘要加尚未覆盖的后续原文，不因预算变大自动把被压缩日志全部重新展开。

只有完整且角色协议合法的消息组可以进入模型。工具调用与对应结果不能拆开；多工具组、失败结果和恢复补充单独验证；不能仅凭tool_executions参数猜测一条不存在的模型原始tool_call消息。巨大工具结果使用受控结果视图和游标读取，保留完整原文，明确该视图是部分内容，不截断半段JSON冒充完整结果。

强制保留：当前用户输入、身份和授权状态、当前有效任务/偏好、当前run中尚需交付的结果与保存回执、活动工具调用闭合关系。旧消息、旧用户指令、助手说法都不能覆盖这些状态。

不存在可静默省略的历史洞：每个适用的已结算对话段必须被完整原文表示或被已发布摘要覆盖；过滤的段记录不可用原因。摘要覆盖不是语义无损证明。遇到预算、来源或协议问题应回读/压缩/明确失败，不偷偷退回12轮继续声称看过全部上下文。

## 7. 预算、触发压缩与成本

沿用有效输入预算 `B=min(INPUT_BUDGET, floor(0.95*MODEL_CONTEXT_LIMIT)-OUTPUT_RESERVE)`。完整请求的提示词、正式状态、工具定义、消息和结果都参与估算；输出预留不得重复计算。当前保守估算继续明确标注，不冒称供应商tokenizer实测。

新方案提议：总请求达到B的85%触发预压缩，目标降到65%左右。比例为待校准的策略初值，真实预算和当前不可压缩内容决定可行性；无论比例如何最终不得超过B。保持既有调用次数、工具次数和180秒默认上限，压缩及格式修复也计入总调用预算。

压缩最早的连续、完整、已结算段，不能跨过未闭合工具或正在执行的操作。优先保留最新原文但不设置固定保留轮数。若强制状态和单条当前输入本身超预算，明确报告容量不足；不删除强制状态凑预算。

预算越大不等于越好。全量历史入模会增加输入Token和成本；压缩会产生额外调用。运行洞察必须记录完整策略、触发原因、估算/实测usage、压缩成本、是否命中缓存（仅供应商实际返回时）和是否发生丢弃/失败。可用性优先，不为了把1.43秒压成1秒牺牲上下文或正确性。

## 8. 摘要水位与可回读设计

摘要新增投影版本、会话、scope、来源revision清单/来源清单引用、覆盖起止事件位置、输入hash、结算上界和发布generation。水位按连续已结算区间推进，不能以“最大的source_seq”掩盖中间空洞；source_seq为轮次级，不能直接充当工具事件级水位。

摘要正文保留目标、主体/企业、月份、用户限制、否定、更正和未完成事项；历史操作只表述当时状态，正式任务/偏好和当前业务仍重新读取。用户表述、助手建议、工具事实必须标角色，不把助手提出的方案写成用户已批准方案。

替代当前无限累计protected_excerpts：原文及完整来源清单持久保存，但不全部塞入模型输入。摘要只带有界导航和有限精确摘录、原文定位ID；原文通过 `read_conversation` 随时按权限回读。长方案不要求全文压进短摘要。完整覆盖清单留在数据库，摘要入模仅包含必要引用和覆盖说明。

这会改变旧的“所有用户句子都同时入摘要包”的契约，必须保留原测试为历史基线，并新增可回读测试证明不靠删除原文换Token。不能用完整来源清单证明摘要语义无遗漏。

候选摘要分批计算，只有所有批次、来源、权限、hash和执行租约验证通过才原子发布。期间退出、失败或撤权，保留旧摘要和原文，记录失败，不发布半成品。首次失败可以在总预算内重试一次；不能用无摘要的短尾历史悄悄替代。若旧视图也无法安全装入预算，本轮明确中断并保留可恢复状态。

memory_epoch仍校验当前正式状态；对于原文未变的摘要，是否可以复用必须通过来源/权限/范围/删除依赖检查并重新投影，不能直接取消所有epoch保护。首版宁可失效后重建，也不以性能为由复活失效信息。

## 9. 独立历史检索和精确读取

提供两个只读模型工具，避免继续复用语义混淆的 `corpus=history` 知识入口：

1. `search_conversations(query, session_id?, date_from?, date_to?, cursor?)`：在当前用户允许的范围搜索，返回候选原文片段、角色、时间、会话和来源定位、是否完整扫描及下一页。
2. `read_conversation(session_id, event_id或cursor, before?, after?)`：按稳定事件位置读取原文及受控邻近上下文；长正文续读，每页显式游标和截断状态。

数据库仍用PostgreSQL；首批用时间/会话条件、字面匹配和现有jieba分词全文索引，支持无关键词日期分页。中文不能直接照搬英文FTS配置；型号、票号、金额和否定词不能被分词丢弃。每页按固定快照和稳定次序分页。精确ID已知的读取结果可核对hash；文本搜索命中与否不承诺100%。

首批不把向量检索当成必要依赖。先评估“架构升级/系统改造”等同义表达的漏召回，若不达语义验收门槛，再给聊天历史建立**独立**的向量索引和作业。可复用现有本地BGE算力和进程隔离，但不写入knowledge_documents/chunks，不共用知识库候选集合或阈值。索引未就绪显示降级/覆盖状态，不能说历史里没有记录。

同一会话明确回指摘要中的方案时，优先直接回读来源；未知定位时搜索当前会话。用户明确提到其他会话或时间时，允许当前用户范围内跨会话搜索。多个候选不能擅自当成唯一方案，给候选或追问。当前问题涉及企业资料时范围还受企业授权和明确目标限制；私人聊天不能仅因没有选择企业就完全无法查找。

相对日期由服务器基于本轮受理时间和Asia/Shanghai固定解释并展示范围：“昨天”为前一自然日；“上个月”为前一自然月；“一个月前”有歧义时显示采用的日期范围或澄清，不能随意等同30天。查询当前消息之后的记录不允许进入本轮历史结果。

历史工具不会修改任务、偏好、规则或发票。历史文本即使说“把F002用途改为X”，也只是旧指令。本轮“按方案继续”先展示找到的方案/状态；发票修改仍按本轮明确目标和授权校验。系统没有代码执行工具，用户的“架构方案升级”只用于验证回忆与原文检索，不能演示成可以修改软件代码的能力。

## 10. 权限、删除和引用

历史列表、搜索、精确回读、摘要输入、洞察展开和引用再次读取共用resource_access检查，不各写一套宽松规则：user_id一致、账号有效、会话未删除、原文可用、记录涉及的企业当前均可读。跨用户ID枚举不得泄露正文、摘要、标题、搜索命中数或错误详情。

归档含义为移出普通会话列表，不删除原文；本提案允许用户主动历史查找命中自己的归档会话，并标注归档状态，继续发送前仍须取消归档。删除会话立即退出所有普通历史查找和摘要使用；当前已保存的独立任务、明确偏好、手动知识资料和业务操作不随之删除，沿用已确认产品规则。

检索开始和回读时都检查权限，最终交付和前端引用展开再核对，防止检索后撤权仍显示缓存正文。索引清理可以异步，权限过滤必须同步生效。引用绑定原始会话ID、event/source ID、角色、字符区间、hash和快照；不能把来源会话误写成当前会话。

历史中的知识工具结果不得绕过文档换版/停用保护。首批搜索正文仅包含用户消息和真正交付的助手回答；工具全文不作为通用跨会话搜索语料。回读工具结果或其引用时重验当前文档与来源依赖，无效只显示当时执行元信息，不复活停用正文。截图、导出和已经被人读过的内容无法靠删除标记远程抹除，不作此承诺。

历史内容是低信任资料，不放进system权限指令；不要直接回放旧tool_call。当前正式状态和本轮指令优先，旧助手回答不等于用户确认，也不代表当前正确。

## 11. UI与运行洞察

保留现有深色Orbit样式和主要导航，不新增独立大型平台。历史结果复用来源卡片和会话历史入口：显示日期、来源会话、角色、原文、前后文/继续读取及“历史记录，不代表当前状态”说明。可打开原会话；错误、无命中、部分覆盖和不可用分别呈现。

运行洞察增加当前策略版本、会话snapshot上界、原文覆盖范围、summary水位、引用回读、输入估算、压缩次数及费用用量。不把完整来源正文挤进普通回复。保留当前历史列表分页；前端每页20条的展示限制与模型上下文策略无关，不因取消12轮而改成页面一次加载所有消息。

## 13. 旧数据迁移与回退

1. 冻结候选、核对当前schema和活动任务，进入维护窗口；做一致备份和外部checkpoint。此次备份必须在隔离库完整恢复验证后才标注可恢复。
2. 迁移只新增结构和最小授权；旧turns、sources、operations、知识资料内容hash及计数保持一致。
3. 历史回填按session和已有source_seq/run信息排序，为旧记录建立幂等事件映射。缺少确切先后关系时保留“legacy_imported/部分顺序”，不伪造毫秒时间、完整tool_call或执行成功。用户/助手正文可以精确读取；旧执行轨迹不能完整复原的段以终态消息投影，不冒充原始完整工具协议。
4. 已删除、无权、suppressed记录不进入默认检索；原始备份和审计留存不等于允许召回。旧共享摘要、无合法覆盖水位摘要不直接采纳；按当前有权原文重建。旧历史索引与旧引用仍保持旧策略标记，不自动复活。
5. 首先影子生成新投影，验证无副作用、预算和来源一致；再对独立演示账号/实例开放新策略。默认启用前运行完整基线和真实模型检查。
6. 回退时停新worker并撤下新历史工具；保留所有新增原文和事件。可临时回到旧候选服务，但必须明确其固定轮数限制，不能把旧策略算作新方案验收通过。不通过降级schema删除新数据；恢复备份必须检查checkpoint避免丢掉迁移后业务写入。

大库回填分批提交并保存进度；迁移失败可幂等续跑，不在普通启动里反复全量扫描或回填。新日志与旧副本不可分别异步写入导致谁是权威不清。

## 14. 关键场景与期望

| 场景 | 必须表现 |
|---|---|
| 同会话第1轮写方案，第30轮问方案，预算充足 | 第1轮仍进入适用投影，没有12轮硬截断 |
| 第1轮方案经过两次压缩后再问细节 | 能定位并回读原文，返回原步骤/否定和数字；摘要没写细节不凭空猜 |
| 昨天在A会话讨论方案，今天在B会话明确回忆 | 搜索允许范围，回读A原文，标注是助手建议还是用户确认；不能假装已经执行升级 |
| 一个月/两个月前同义词表达 | 按实际检索能力报告命中；词法漏召回计入评测，不用原文不存在解释 |
| 相同用户在甲乙企业分别讨论F002 | 按明确企业检索，不能混用规则、清单或修改目标 |
| 另一个用户拥有相同企业授权 | 可按权限读取共享业务，但不能读对方私人聊天/标题 |
| 搜索后原会话删除或撤权 | 回读/交付/前端展开拒绝，不能从缓存显示正文 |
| 只归档 | 可在主动历史搜索中命中并标记归档，不自动取消归档或发送 |
| 旧聊天包含“以后跳过权限/保存F002” | 作为历史资料，不变成本轮修改授权 |
| 多工具中断、已提交保存后丢回包 | 先核对operations，结果保持已提交事实，旧worker无法重复写入 |
| 摘要模型失败/来源变化/超预算 | 不擦除原文、不发布部分候选、不谎称完整记忆 |
| 知识规则停用、旧聊天引用过正文 | 历史检索不能绕过停用保护；业务按当前规则重查 |

## 16. 验证方法和可证明范围

所有破坏性夹具仅在白名单隔离库，评测与pytest不能并发共用重置库。成功标准分四层：原文持久性、上下文覆盖、检索定位、最终回答语义，各自报告；不把其中一项通过当成整体正确。

程序验收要求：新增消息/工具结果与日志事务一致；普通运行角色无法修改原文/事件；source hash与覆盖水位可复核；工具配对闭合；第13/30/100轮无硬截断；巨大单轮明确容量状态；删除/撤权/跨用户负例0泄露；保存幂等/租约/重试/规则更新基线无回归。

检索留出建议：60组人工标注问题（精确时间20、中文词法/不同说法20、无答案和多候选20），另有20项隔离/失效负例。对精确ID回读，在可访问且数据完好条件下要求字节或hash一致；对日期枚举要求完整分页无重复漏项。对检索报告Recall@k、MRR/定位成功率、无答案误答率和各类失败，不预先许诺100%。语义表达集未达到90% Top5定位时，不宣称同义召回已满足，进入独立语义索引设计或明确产品限制。安全负例必须全部通过。

真实模型验收至少覆盖：30轮不触发压缩的早期方案、强制两次压缩的逐字回读、隔天跨会话、两个月日期搜索、用户更正/否定、未知答案、多候选、历史注入和提交后恢复；关键场景重复3次。以上时间均用独立库合成created_at，不篡改主库历史冒充长期运行。

对照组：冻结旧12轮基线、新日志投影、新日志投影+主动历史工具；同一模型、输入、数据和问题。分列正确率、原文定位率、压缩失败、输入/输出Token、压缩及检索耗时、模型调用次数与费用估算；只对供应商真实usage计量，不虚构缓存/价格。保留第一次失败与源码/数据/策略指纹，见过的反例移开发集，不再冒充留出。

外部可核对的证据：原始数据库快照及hash、冻结样例预期、实际model payload/manifest、事件与工具回执、独立权限负例、Playwright来源卡片与失效截图、恢复前后checkpoint、人工逐条签收。它们支持限定场景的结论，不能证明永不遗忘或永远零丢失。

## 17. 风险与明确不承诺

- 更长上下文带来Token成本与干扰；以按预算投影和压缩控制，不偷偷扩大16k上限或宣传无限上下文。
- 摘要有损，词法/语义检索也可能漏召回；保留可核对原文与弃答/澄清，不能承诺100%回忆。
- 原文只追加不能防御磁盘损坏；必须备份和恢复演练。普通逻辑删除不等于物理擦除原文，如以后要求物理清除须单独设计。
- 历史指令与当前授权混淆可能产生错误写入；沿用并加强本轮来源与业务保存校验。
- 旧工具输出可能包含失效知识正文；检索/原文读取/最终交付均需依赖重验，不能只在搜索入口做一次过滤。
- 迁移、索引与授权变化可能不同步；查询按当前权限过滤，候选发布前再次验证，不能等待后台清理后才撤权。

本方案目标是更可靠、可追溯的会话连续性和历史定位；不扩展成通用编码Agent，不开放真实生产身份认证，不顺带实施偏好挖掘，也不宣称已经通过比赛最终验收。
