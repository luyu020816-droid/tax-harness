# 后端加强：首批边界与验收

用户已授权按生产审查结果加强后端，随后明确“暂时只用于比赛演示，先做好生产禁用保护”。本批保留模拟身份，不新增密码或SSO；production模式拒绝启动。处理权限、登录撤销、请求准入和资源边界。

1. 会话列表/完整历史/归档/消息/待补事项/运行详情统一检查当前企业授权和模型输入依赖，不仅检查owner。失去权限的会话不返回原文标题，标题最多120字符。
2. 保留会话私有、企业业务按授权共享的现有边界；不删除数据，不放宽权限。
3. 登录token仍由服务端存储并校验，增加撤销、全端退出和账号禁用能力。Cookie保持HttpOnly/SameSite Strict；生产要求Secure与可信认证，默认比赛入口保留。
4. SSE每次读取事件都验证登录仍有效，再验证轮次和企业权限；失效后只终止流，不返回后续私有事件。
5. 普通请求和恢复请求使用数据库事务内准入：每用户速率、每用户待处理数、全局待处理数有上限；幂等重试先返回已有结果，不因限流重复受理。
6. Agent全局活动执行数通过数据库锁保护，多服务进程共享上限；同用户仍串行，跨用户按最早排队时间领取。保留租约与fencing保护。
7. JSON请求与文件上传有实际字节上限，拒绝超大请求时不写业务。数据库查询使用有界statement/lock timeout，超限明确返回重试反馈。
8. 本批不承诺账单硬预算、任意并发容量、跨机高可用或完整账号系统；身份源选择后补相应发行与管理流程，不用demo冒充真实认证。
9. 独立测试库验证：撤权标题、跨用户/跨企业/依赖授权、Cookie撤销、SSE撤销、禁用账号、并发准入与幂等、全局执行上限、公平领取、超大请求、保存竞态。现有业务/知识/恢复回归继续执行。
10. 原库升级前确认无活动请求并备份，仅增量迁移；比对原文档/发票/规则/任务/偏好/账本字段不变，服务保持8105。最终状态分别记录代码实现、测试、身份接入和容量实测。
