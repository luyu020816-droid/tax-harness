# 第一阶段功能说明与独立验收指南

版本日期：2026-11-17
适用范围：复赛第一阶段——Agent 管理、能力组织与复用。本文供未参与开发的人员独立操作、留证和提出问题。请以验收时的 Git commit 为准填写记录，不要把本文既有测试结果当作本次验收结论。

## 1. 依据、目标与目前状态

赛题原文见《赛题二：财税+Agent+Harness+系统设计与实现复赛要求》PDF 第 1 页：要求通过配置管理不同职责的 Agent（提示词、模型及能力权限），无需修改或复制代码，并考察配置变更范围和权限隔离；还要求按任务组合复用 Skill、Tool 和知识，管理版本、启停、变更影响与未授权调用。PDF 第 2 页要求从作品原入口操作，结合业务数据、日志、实际模型输入和回复判断。

下文的具体交互、AC 编号和安全规则，是团队将赛题细化到[第一阶段 PRD](复赛第一阶段_PRD_Agent管理与能力复用_v1.0.md)的验收方案，不是比赛文件逐字列出的规则。复赛其余六项能力及自主创新不在本文范围。

**状态：核心功能已实现，整阶段尚未完成独立验收。** 既有验证是开发侧证据，见[实施进度](复赛第一阶段_实施进度.md)。下面“预期”均为待独立人员验证的目标，而非宣称验收已通过。

## 2. 环境与记录方式

当前机器若演示服务仍在运行，访问 `http://127.0.0.1:8199/showcase.html`，登录“测试用户一”（U001）。这是隔离演示库，含比赛模拟数据，两个示例 Agent 为“财税办理助手”和“知识查阅助手”，默认共享“发票与规则核对” Skill；它不是原业务数据库，其他机器不能直接使用该 127.0.0.1 地址。

在其他机器上，先按[作品使用说明](../作品使用说明.md)与 [README](../README.md)准备 Python、PostgreSQL、前端和模型；新环境初始化。已有业务库须先备份并对隔离副本验证迁移 017—023，普通启动不会自动升级。真实模型供应商凭据由本机维护者自行配置，不放入文档、截图、运行记录或代码。测试人员应确认页面没有标记程序测试模式；`ScriptedModel` 是模拟模型，不能作为真实模型验收。

每一项记录：日期、验收人、`git rev-parse HEAD`、环境及数据库是否隔离、模型及是否真实、账户／企业／会话、前置配置、操作和输入、期望、实际、通过／失败／未测、截图及运行记录链接或编号。失败保留原始证据和复测记录。测试停用、修改、写入和重启前确保使用隔离库；操作后恢复测试配置。

## 3. 功能与验收步骤

### F01 Agent 创建、版本、启停与选择（AC-01、02）

**目标：** 不改代码创建不同职责的 Agent；草稿未发布不影响现行版本，新请求绑定发布版本，可停用。

**已实现：** “Agent 管理”中的 Agent 配置支持名称、职责说明／提示词、模型、工具动作、Skill、知识范围，保存草稿、发布及启停；主界面“当前 Agent”选择已启用配置。运行绑定 Agent 及版本。

**操作：** ① 登录 U001，记录两个默认 Agent 和版本；② 新建“验收查询助手”，填职责提示词“先核对企业”，授权 `query_month`、`resolve_scope`，选择默认模型、不使用知识；③ 保存草稿，确认尚不能作为已启用 Agent 使用；④ 发布、启用，关闭管理窗，在顶部选择该 Agent；⑤ 输入“查询甲企业2026年9月月度资料”，记录输出及运行详情的 Agent／版本和工具；⑥ 编辑提示词、保存但先不发布，发起一轮并记录版本，再发布并发起新轮，核对版本变化和另一 Agent 不受影响；⑦ 停用测试 Agent，确认不能再选择发起新请求。

**通过标准：** 草稿与发布区分；每轮实际 Agent 和版本与当时生效配置一致；停用后不能新发；记录真实响应。还需单独安排运行中的版本切换测试，不能仅凭两个顺序请求证明。

### F02 Tool 共享、动作授权和停用（AC-03、04、07）

**目标：** 一套工具供多个 Agent 使用，同时仅按各自授权和用户企业权限执行；停用立即阻止新调用及未提交副作用。

**已实现：** 使用已有工具注册表，按 Agent 和动作筛选模型工具，并在执行时再次检查；工具全局停用覆盖原助手，知识别名按最终目标校验；目录展示状态、保守风险分类、源码包与契约摘要。

**操作：** ① 分别编辑两个测试 Agent，授权 `find_invoices`，发布启用后分别请求“查询甲企业发票 F002”，在运行详情核对实际工具及各自 Agent；② 对只读 Agent 不授权 `update_invoice`，要求其修改发票，核对没有未授权的业务更新；③ 在“工具启停”停用 `find_invoices`，对两个 Agent 和“原助手”重新查询，核对该工具不再实际执行；④ 恢复启用，确认依然需要各自授权。停用前后截图并记录受影响 Agent。

**边界：** 模型不主动尝试调用写工具，不证明服务端拦截。开发人员须另运行 `backend/tests/test_agent_authority.py` 和 `backend/tests/test_agent_capabilities.py`，复核构造的写入、别名及动作越权反例，并检查数据库无新增未授权业务操作。源码包摘要不是单独工具实现版本，亦不覆盖第三方依赖。

### F03 Skill 组合与复用（AC-06、08）

**目标：** 能力指引可独立版本化，被多个 Agent 复用；Skill 依赖不会自动获得工具权限；停用 Skill 不应自动停用 Agent 直接授权的工具。

**已实现：** “Skill 配置”可新增、编辑发布、启停并配置工具动作／知识依赖；Agent 发布时检查依赖，运行使用绑定版本。

**操作：** ① 查看默认 Skill，分别编辑两个 Agent，核对均可选择该 Skill；② 新建“验收查询 Skill”，写明核对票号，依赖 `find_invoices`；③ 在未授权该工具的测试 Agent 选择 Skill 并发布，预期提示缺少授权且不发布；④ 授权后发布，第二个 Agent 也选择同一 Skill；⑤ 可再创建第二个 Skill，验证一个 Agent 可组合两个；⑥ 停用该 Skill 后新发请求，检查不再加载其指引；确认 Agent 直接授权的 `find_invoices` 未因此全局停用。通过运行详情或实际模型输入留证。

### F04 知识范围与资料复用（AC-09、13、16）

**目标：** 按 Agent 范围复用知识，且原用户／企业授权、资料有效状态继续生效；撤权或停用后旧资料不能继续作为有效依据。

**已实现：** 知识范围支持“不使用知识”“当前用户有权访问的知识”“指定资料”，可选择当前企业的有效资料并分页；检索、引用回读和受限 Agent 上下文增加范围约束。

**操作：** ① 在隔离环境通过原知识入口准备并发布两份可区分的模拟资料 A、B；② 配置 Agent A 仅选择 A、Agent B 仅选择 B，并明确授权 `search_knowledge`、`read_evidence`；③ 分别提问 A 和 B 中才有的内容，检查答案及引用是否在对应范围；④ 两个 Agent 再共同选择同一资料，验证复用；⑤ 将其中一个 Agent 的资料授权取消并发布，或停用资料，再尝试原问题及引用回读；⑥ 切换用户／企业复测不泄露无权标题和正文。

**留意：** 测试前核对资料已完成解析、发布，且问题确实有答案。模型答非所问需检查运行详情，不能只看界面文字判断越权。历史消息、附件及运行中撤权组合尚需专项验收；受限 Agent 暂不支持手动 `/compact`。

### F05 独立模型配置（AC-01、10）

**目标：** 不同 Agent 可引用独立测试的模型配置；失败不覆盖可用配置；重启或模型不可用时不能静默冒充成功。

**已实现：** 在“Agent 管理 → 模型配置”填写配置编号、名称、地址、模型名和密钥后测试；Agent 可绑定模型配置及版本。密钥仅存服务进程内；失败保留旧配置。

**操作：** ① 维护者分别提供两套有效模型配置，在本机页面测试，记录配置编号与测试结果，不记录密钥；② 两个 Agent 分别引用不同配置，发布、启用后执行相同的授权查询；在运行详情检查绑定模型配置及真实输入；③ 以错误配置测试其中一套，确认失败且旧可用配置不被覆盖；④ 在隔离环境重启服务，观察页面配置的密钥失效和不可用提示；重新输入测试后发布新的 Agent 版本，再验证。默认环境模型与页面模型不是同一存储机制。

**已知证据：** 开发侧真实模型测试使用同一套模型配置完成两种职责，不代表两套独立真实模型已经验收。

### F06 权限、撤权、发票确认与回执（AC-05、11、12、17、18）

**目标：** Agent 授权不能扩大用户及企业权限；非管理用户不能配置；撤权先于提交时不能写入，先提交后撤权时真实回执保留。

**已实现：** 模拟 U001 为配置管理者；管理 API 要求本机同源和管理权限；发票计划保留来源 Agent，确认和提交重新校验能力，撤权与事务提交使用共同锁。

**操作：** ① 切换“测试用户二”（U002），尝试管理 Agent／模型和访问无权企业，确认后端拒绝且无数据泄露；② U001 在测试 Agent 发起需要确认的发票计划，记下票号和原值；③ 确认前停用 `update_invoice` 或撤销该 Agent 的写入权限并发布，再点确认；检查未产生业务变更；④ 在另一独立样例先完成授权写入并取得回执，再撤权，检查既有回执仍在且没有重复操作；⑤ 恢复工具配置。

**技术复核：** 本机／同源伪造、并发竞争、写入前后顺序需配合 `test_agent_admin_api.py`、`test_agent_authority.py` 及数据库审计，界面隐藏按钮不能证明服务端安全。真实并发、独立导入页面与原库升级仍需单列现场证据。

### F07 运行追溯（AC-13、16）

**目标：** 能从原入口核对用户、会话、Agent 和模型配置版本、模型实际输入、工具调用、拒绝原因与业务回执。

**已实现：** 原有运行详情增加 Agent 绑定、版本和模型信息，保留工具与上下文追溯；访问仍受既有用户／企业权限约束。

**操作：** ① 选择 Agent 执行 F01 查询；② 打开该轮运行详情，截图 Agent 名称／版本、模型配置、工具名称、模型输入及结果；③ 同一会话切换 Agent 再发，分别核对两轮；④ 切换用户及企业，尝试访问无权内容；⑤ 在一次运行中途撤权，再检查是否继续发送受影响输入或执行写入。

**注意：** 源码／契约摘要不等同完整运行时依赖版本；记录中不应出现 API Key。模型请求一旦发出不能撤回，后续调用和未提交操作应按当前授权处理。

### F08 旧库兼容与原功能回归（AC-14、18）

**目标：** 升级不损坏原会话、资料、发票或确认流程，不给旧轮次伪造 Agent 信息。

**已实现及限制：** 迁移 017—023 和示例初始化已实现。人工构造的旧结构样例库升级测试通过；**尚未对现有业务库隔离副本完成全量核对**。

**操作：** 由具备数据库管理经验的人员先备份、恢复到隔离实例并核对身份，记录升级前会话、知识、发票、用户授权和回执的数量及抽样内容；对副本应用迁移；逐项核对数据、旧轮次绑定、查询、知识和原有发票确认／导入；保留备份与差异报告。禁止在正式库直接试错。

```powershell
$env:PYTHONPATH = 'backend'
python -m pytest backend/tests/test_agent_profiles.py backend/tests/test_agent_capabilities.py backend/tests/test_agent_authority.py backend/tests/test_agent_context.py backend/tests/test_agent_knowledge.py backend/tests/test_agent_runtime.py backend/tests/test_agent_admin_api.py -q

```
