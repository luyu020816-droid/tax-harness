## 1. 目标与赛题依据

复赛要求第 2 页的「文件处理」考察 Excel、Word 和文字型 PDF 的解析，文件来源、版本和权限管理，以及复杂内容查询、金额计算、依据定位、重复上传和更新控制。现场通过作品原入口查看业务数据、日志、实际模型输入和答复。第二阶段首批以 **新上传的 Excel 可查、可算、可回查** 为交付目标。Word、文字型 PDF 用作兼容性回归；完整文件生命周期组合在第二批扩展。

验收时，评委用一个有权访问的 Agent，从现有工作台上传一份未预置的模拟报销明细，询问某月实付合计及类别分项，能核对从原表行到总额的全过程。随后可以在同一会话更改月份和类别，取得重新计算的结果及引用。

首批支持 `.xlsx`、单文件单工作表、表头明确的报销明细、人民币元、日期区间及费用类别的精确筛选、金额求和、行数、可选按类别分组。一个工作簿可含多个可选工作表，每次计算选择其中一个。跨表合并、复杂工作簿、公式重算、自动列映射、其他格式（如 `.xls` 和 `.xlsm`）、多币种和财税账本写入均在首批范围之外。新增能力以只读方式接入第一阶段权限体系。

## 3. 从页面到业务结果

1. U001 在工作台选择有权限的企业，从知识资料上传 Excel。上传后显示文件名和处理状态。解析失败时展示原因，文件不进入问数候选。可用状态中可以查看工作表及列识别状态，并选择对应资料加入当前对话。
2. 选择已授权表格工具的 Agent。若当前只有一个明确引用的已发布 Excel 和一个可查询工作表，程序允许直接使用。存在多个文件、多个可查询工作表、未明确的时间范围或金额列歧义时，助手发起有针对性的澄清。用户明确要求「整张表全部日期」时可以无日期筛选。
3. 用户问「2026 年 10 月实付报销合计多少，按费用类别拆开」。模型确定查询参数，后端验证当前权限、工作表、金额列、时间范围及类别，再从完整明细执行计算。
4. 回复显示币种／单位、实际筛选范围、合计、参与行数、类别分项及可展开的来源。通过来源打开当前有效文件的工作表、金额列和参与行。运行详情同时显示 Agent 版本、工具参数、结果标识和状态。
5. 追问「改成 11 月，只看交通费」。同一会话、同一 Agent、来源唯一且仍可用时，沿用明确的文件、工作表和金额口径，以 11 月和交通费重算。切换企业、Agent 或存在多个可能来源时，要求重新确认。旧结果不能替代新查询。

## 4. 解析和计算规则

- **表格边界。** 首批上限为 5 MiB、20 个工作表、每表 10,000 个非空数据行、50 列；稀疏或伪造的超限工作表也必须在受控读取边界退出。复用归档解压约束。只处理可见工作表；有隐藏行或列、合并单元格、疑似汇总行的目标工作表标为不可计算并给出理由。空行忽略。第一条非空行作为表头，不支持多行表头。
- **表头识别。** 去除首尾空白并统一全半角，按固定别名匹配日期（日期、报销日期、支付日期）、类别（类别、费用类别、费用类型）、金额（实付金额、实际支付金额、报销金额、金额）。任意必需字段缺失时说明缺哪列。多个候选时列出原始表头及列字母，由用户确认对应列。用户问实付时不得默认为「申请金额」或其他口径。列顺序不影响解析。
- **日期与类别。** 支持 Excel 日期单元格及可明确解析的 `YYYY-MM-DD`、`YYYY/MM/DD` 字符串。月份查询换成含开始、不含结束的日期区间。类别使用规范化后的精确匹配，不擅自把不同类别合并。筛选与分组同时生效，分组覆盖全部匹配行。
- **金额。** 首批口径是人民币元，读取普通数值或可无歧义解析的十进制文本（可识别规范千分位），允许负数和真实零。读取 Excel 数值的原始十进制表示，用 `Decimal` 累加，金额以十进制字符串返回。数值单元格允许分位附近的 Excel 序列化尾差，比如 `79.90000000000001`。文本金额和真正超过两位小数的数值拒绝计算。外币、超范围数值、公式、错误单元格和参与计算的空值均提示具体单元格。
- **聚合范围。** 日期无效导致范围无法判断时，拒绝给出合计。能够确定某行在范围外时，其金额无需参与计算；命中范围内的无效金额拒绝本次聚合并指出来源行。需要类别筛选或分组时，缺失类别且无法判定归属的命中日期行应报错。明细有效但无匹配时交付「0 行，合计 0.00 元」。数据无效时返回失败状态，不能展示同样的零结果。原表重复的明细行按物理行重复计入，不自行按金额或文本去重。
- **分页和上下文。** 程序对完整匹配集聚合。模型可获得有界结果与定位预览，界面可分页查看全量匹配行。预览截断不影响金额；过多分组无法完整展示时明确提示并分页，不返回“已列齐”的假象。整份工作簿及全量行不进入模型输入。

## 5. 服务端、工具及证据契约

### 5.1 资料与作业

复用 `/knowledge/uploads`、资料版本和作业状态。资料增加可判定的表格类型，原始 Excel 和 SHA-256 仍由现有资料记录持有。解析成功后产生以 `version_id` 唯一绑定的不可变表结构快照，包括解析版本、工作表列表、原始列标题、列字母、原始物理行号、类型、可计算状态和规范值。首批可使用受限大小的结构记录，不为未来跨表查询引入存储引擎。

解析作业沿用现有权限、超时、租约及原文件哈希核对。表格就绪由同一事务内完整的结构快照决定，文本资料继续校验索引就绪。表格不进入文本向量检索候选，也不作为正式规则的可执行依据。若新工作簿无可计算工作表，显示原因并且不替换原有效版本。首次接入按现有私有资料流程生效，失败或重试时保持原状态。

上传重试沿用请求 ID 幂等。不同请求 ID 的同内容上传在第二批做显式识别。首批同名上传不得隐式覆盖原资料，替换必须通过已有的版本入口和 revision 校验。发布后查询只用当前有效版本，引用不得把旧版内容标为当前。停用或撤权后不能通过旧附件、追问、链接或伪造 ID 继续取得行数据。

### 5.2 工具

| 名称 | 输入 | 输出 |
|---|---|---|
| `inspect_workbook` | 已授权且来自可核验上下文的 `document_id` | `version_id`、文件名、工作表、可查询状态、候选列及拒绝原因。只返回必要元数据。 |
| `query_workbook` | `document_id`、已解析的 `version_id`、工作表、日期／类别／金额列映射、`date_from`／`date_to_exclusive` 或显式全表、可选类别、`group_by`（`none`／`category`） | 成功时返回 `result_id`、标准化范围、单位、十进制合计、匹配行数、分项、来源标识。失败时返回可定位的原因，无成功金额。 |

列映射只能选解析结果公开的候选列。后端检查列映射、范围及显式全表参数，日期区间与全表标记互斥。用户要求特定口径时，工具及结果都记录最终确认的原始金额列名，便于核对。

两工具均为明确注册的只读能力，在 Agent 配置中可独立启停和授权。服务端使用请求绑定与当前授权的交集核验，遵守 Agent 的 `none`／`selected`／`authorized` 知识范围与现有用户／企业权限。保留旧工具默认授权逻辑；新增工具按现有配置流程给测试 Agent 显式授权。Agent 更换、资料停用、换版和撤权发生时，检查当前版本和授权；发生在组装之后的变更应阻止后续模型发送旧数据及交付旧结果。无权限时不泄露文件名和默认候选。

### 5.3 结果与引用

结果在服务器绑定执行用户、企业、Agent／会话、工具调用、文件版本、解析版本、查询条件和全部参与行定位。结果卡引用 `result_id`；模型只能引用本轮经验证的结果，卡片由程序读取真实记录生成金额及范围。缺少有效结果、伪造结果 ID 或引用不匹配时不得交付精确金额。模型可解释计算范围，不独立输出未经工具验证的金额。

来源展示原文件名、版本、工作表、列字母及准确物理行号或连续区间。如只命中第 2、4 行，展示两处定位，不能显示第 2–4 行为全部依据。详情可分页显示参与行，使用既有有效原文件入口核对原表。回读时重新校验当前身份、企业、原引用和版本有效性；历史消息可以保留当时的结果状态，失效来源标为不可用，后续回答不能从历史上下文恢复该来源内容。

## 6. 开发顺序与验收

1. **解析及精确计算。** 先用样例打通类型识别和行定位，严格失败；通过 X-01、X-02、X-03、X-04 的可重复离线检查。
2. **上传、资料版本、工具和授权。** 接已有上传与解析作业，注册工具，验证文件版本和权限，结果及来源可回读；通过 X-05、X-06、X-07 的隔离数据库检查。
3. **工作台、上下文与展示。** 从原入口连通上传、授权、查询、追问、运行详情和来源回查；过 X-08、X-09、X-10，并保存证据。每步通过后再扩大覆盖。

| X-07 | 替换、停用资料后尝试利用旧版本结果；向回复提交其他轮次的 `result_id`。 | 旧版本不可再次计算或作为有效来源回读，越轮结果无法生成本轮金额卡。 |
| X-08 | 在原工作台依次上传、选资料、用真实模型运行 X-01、打开来源；随后追问「改成 11 月，只看交通费」。 | 两轮均有真实工具及运行记录，第二轮是 88.50 元、1 行、定位第 6 行。 |
| X-09 | 换一份未参与开发的模拟明细，列名使用支持的别名，调整列顺序与数值；切换企业后再试。 | 人工复核金额、范围和定位。切换企业后不沿用旧文件。 |
| X-10 | 走原入口测试 Word、文字型 PDF 上传引用，并执行原固定模板 Excel 导入的离线回归。 | 原路径和行为仍通过。表格问数无发票／银行／报销账本写入，必要时以数据库操作记录核对。 |

交付签收要同时具备离线结果、原入口真实模型轨迹和可核对的原表来源。验收记录包括 commit、输入文件哈希、Agent／工具版本、实际查询参数、人工合计、行定位、错误或拒绝状态。第 X-08 项须留页面及运行详情；脚本模型只能验证程序流程，真实模型是否符合预期单独记录。

第二批在上述链路通过后补齐跨请求内容去重、换版／停用／多轮交叉场景、覆盖更丰富表格形态的实际需求，并扩大 Word、文字型 PDF 与 Excel 的统一入口验收。
