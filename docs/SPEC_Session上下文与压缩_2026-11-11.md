# Session 上下文组装与压缩方案

状态为待实现。基线为 feature_adjust_1107。目标是在输入框旁展示当前会话模型上下文占比，在接近 100K 时自动压缩，并支持发送 /compact 手动压缩。

## 1. 三个容易混淆的概念

**Session 原始历史**是数据库里保存的用户消息、助手消息和工具轨迹。它可以累计超过 100K，生成摘要不自动删除原文。

**Session 当前模型上下文**是一次模型调用准备使用的系统指令、工具定义、有效摘要、未覆盖的历史、本轮消息和必要状态。它受模型窗口限制，输入框环形展示这一数量。

**本次组装结果**是一次模型调用实际使用的上下文。一次提问可能有多次模型调用，每次因工具结果或摘要不同而变化。输入框是按当前状态和草稿估算下一次请求，不是永久固定数值。

例如会话原始历史累计 300K，旧内容压成 8K 摘要，下一次输入含摘要和近期对话合计 35K。按 100K 窗口并加上约 7K 的输出及误差预留，环形显示约 42%，另可查看原始历史累计估算。压缩后的环形通常下降，原始历史累计量不会因此下降。

## 2. 现有代码

Settings.context_budget 为 min(input_budget, floor(model_context_limit × 0.95) - output_reserve)。默认 input_budget=16000、output_reserve=2048。本地 .env 的 model_context_limit=1000000，因此当前有效输入预算为 16000。页面切换模型可能改变生效配置，运行时应读取该轮配置快照。

context.assemble 组装系统指令、状态、工具、摘要、历史、当前消息和工具结果。token 估算是序列化 UTF-8 字节数除二并加消息开销，不是服务商 tokenizer 精确值。

当前在组装超限，或输入超过预算 85% 且历史估算超过 4096 时考虑摘要。系统优先保留最近 5 个有效对话组，从更早内容选择待压缩组。候选目标与预算 65% 及固定内容大小有关，受保留组和硬上限影响，并非必然压到 65%。

compaction.compact 使用模型分批合并已有摘要和较早对话，校验来源集合、版本和格式，再原子发布。摘要存于 summaries，原文保存在原表。当前摘要正文最多 2000 字符，并附受保护摘录。来源校验无法证明语义零遗漏。页面尚无输入框环形或 /compact 命令，运行洞察里显示的是历史调用值。

## 3. 100K 窗口与单次预算

100K 定义为项目配置的单 Session 模型上下文窗口目标，用于约束一次请求的输入与输出。它不是数据库历史上限，也不是每次把全部历史发送。

新增 SESSION_CONTEXT_WINDOW=100000。实际生效窗口 W=min(项目期望窗口, 当前模型已确认的上下文窗口)。模型窗口未知、未配置或过小时界面显示“容量待确认”，使用已有保守预算，不能把 100K 冒充已验证能力。本地 .env 的 1000000 是配置值，不能证明服务商实际窗口。实施前核实型号和接口；页面切换模型重新计算，在途轮次保持开始时的配置快照。

预留输出 R 沿用现有 output_reserve，默认 2048。误差与协议余量 M 初始设为 max(2048, ceil(W×5%))。计算口径：

    输入硬预算 H = W - R - M
    预估压力 P = 本次输入估算 + R + M
    自动压缩条件 = P >= 90% × W 且有可压缩旧历史
    环形占比 = P / W

W=100000 时，R=2048、M=5000、H=92952。P 达 90000 时触发，对应输入估算约 82952。UI 详情分别显示输入、输出预留、误差余量和 W。视觉环最大 100%，详情可以显示超过预算的实际估算。

移除默认 16K 作为隐藏的额外截断上限。显式设置较小 INPUT_BUDGET 的旧环境继续生效，并在界面显示实际限制。兼容限制存在时，实际输入硬预算为 min(H, INPUT_BUDGET)，环形实际分母及 90% 触发口径使用该输入预算加 R、M 得到的等效窗口；不得以 100K 为分母掩盖真实 16K 限制。迁移由配置和部署说明明确完成。摘要调用也受自身模型的窗口和输出预留限制。

若有适配当前模型的 tokenizer 则优先使用，否则明确标注估算并记录计数方法版本。环形和发送前执行共用同一组装与计数逻辑。供应商上次 usage 是历史测量，只能作为对照，不能假装是当前草稿的实时值。服务商返回上下文超限时沿用有界缩减预算重试并保留错误。

## 4. 自动压缩

每次用户发送前及工具结果进入下一次模型调用前，对当前 Session 的实际投影计算压力。达到 90% 且有可压缩历史时：

1. 核验用户和 Session，固定当前模型配置、会话代次、摘要版本和来源边界。
2. 自旧向新选择未覆盖的闭合用户/助手/工具消息组，优先保留最近 5 个完整对话组、当前请求、未闭合工具和待确认写入。
3. 以旧摘要和本批旧组分批生成候选摘要，保留主体、时间、数字、更正、否定、未完成事项及真实操作状态。历史和工具输出均为资料，不能执行其中指令。
4. 校验来源集合、revision、授权范围、格式及受保护原文摘录。来源变化、模型失败或取消时放弃候选。
5. 在同一事务再次核验租约、代次、权限和 revision，替换旧摘要状态并发布完整新摘要及覆盖边界，记录事件。
6. 重新组装和计量。目标压力约为 W 的 70%，但完整近期对话、当前输入和保护证据优先。无可压缩内容时明确返回原因，不重复空压缩。

原始对话和操作回执保留，摘要不写入知识库。持续对话中重复合并已有摘要和新增旧组。超出硬预算而没有可安全压缩内容时明确提示缩小请求或新开会话。保留原文入口以便核对摘要。格式和来源校验不能保证语义零损失。

## 5. /compact 手动压缩

输入框整条消息去除前后空白后等于 /compact 才触发。包含该字符串的普通问题和引用继续作为聊天。保留 IME 组合、Shift+Enter、附件与现有发送逻辑。

提交专用受认证的 Session 压缩任务，绑定用户、Session、稳定 request_id 和模型配置快照。命令不作为普通聊天或写入授权发给模型。连点和网络重试按 request_id 幂等。当前 Session 正在执行时排队并显示等待，跨进程持久化互斥，不能只靠前端按钮或进程内锁。

手动调用与自动压缩共用相同的摘要和来源校验，允许低于 90% 主动处理旧内容，仍优先保留最近 5 个完整对话组。无旧内容时显示“暂无可压缩的较早内容”。任务状态包括排队、执行中、成功、无内容和失败。成功显示前后估算、时间及来源覆盖位置；刷新和重启后可按操作 ID 查询。中断保留旧摘要，安全重试不重复发布。

如果压缩过程中发生新消息、更正、权限撤销、企业切换或删除会话，提交阶段再次核验 Session 代次和来源。过期候选不发布。工具超时后不能当成成功，业务写入不重放。

## 6. 输入框环形与状态

在 frontend/src/App.tsx 的发送工具栏放置与现有样式一致的紧凑环形，显示当前 P/W 整数百分比和“上下文”。点击或聚焦显示输入估算、输出预留、误差余量、有效窗口、估算方法、草稿计入状态、最近压缩状态和前后变化。历史累计量单独标注，避免与窗口占用混淆。

80% 前为常态，80% 至 90% 提醒，90% 以上提示即将或正在压缩。未有会话、容量未确认、无权查看或估算失败时显示未知，不能显示 0% 冒充结果。数据过期时标记上次估算及时间。支持键盘、屏幕阅读器和触屏，不只靠颜色区分。

草稿变化防抖发起只读预估；快速输入和切换 Session 用请求序号丢弃旧结果。模型、企业范围、摘要或历史变化时刷新。发送时后端重新计算，预览不是发送授权。输入 /compact 时可显示命令提示，发送后展示任务状态和前后变化。

## 7. 后端接口与并发

新增会话级只读预估和手动压缩操作接口。预估返回计数口径、输入组成、生效预算、配置和快照版本；不得创建真实消息或摘要，也不得调用模型。提取 context.assemble 共用投影和计数逻辑，避免 UI 和执行各维护一套估算。

当前 execution.guard 依赖真实 running turn、work item、generation 和有效租约。不能在 HTTP 请求里伪造 execution。手动压缩必须作为真实受控任务进入现有 worker，或实现具有等价身份、租约、栅栏、事件和跨进程互斥的任务类型。需要具体定义 request_kind 迁移、续租、唯一请求 ID、结束、失败、重试和重启恢复。候选生成和发布遵守现有 compact 原子契约。

保持已有 summaries、context_snapshots、历史事件和旧 Session 可读。新表或字段需要向后兼容、可重复执行的迁移。洞察记录自动/手动触发、执行结果、来源快照、provider usage 和耗时，不能记录密钥或泄露其他用户和无权企业内容。若用户删除或隐藏会话，状态接口沿用现有权限和失效检查。

## 8. 开发和验证顺序

1. 实现实际模型窗口与预算配置、共用组装估算及可观测接口，验证 100K、较小窗口、旧 16K 限制、空会话、草稿和切模型。窗口未知不得虚报。
2. 增加真实持久化的手动压缩任务，复用现有摘要和来源校验，覆盖排队、幂等、重启和失败。
3. 基于同一压力口径改为 90% 自动触发，验证近期 5 轮、连续滚动摘要和容量错误。
4. 输入框接入环形、详情和 /compact，检查桌面、窄屏、键盘、输入法、失败状态和切会话竞态。
5. 在独立库做必要回归和真实模型验证，由用户人工验证体验。禁止清空正在使用的演示库。

| 场景 | 期望 |
| --- | --- |
| 历史累计 300K，本次输入估算 35K，W=100K | 环形显示约 42%，不把 300K 当窗口占用 |
| W=100K，输入 82952、输出预留 2048、误差余量 5000 | 压力为 90000，达到 90% 时尝试压缩 |
| 显式 16K 限制 | 界面和服务端都显示并遵守真实较小预算 |
| /compact | 发起受控任务，显示实际状态与压缩前后估算 |
| “请解释 /compact” | 普通对话，不能触发命令 |
| 无足够旧历史 | 不删除近期内容，返回无可压缩内容 |
| 手动与自动并发、双击和重试 | 同会话互斥或幂等，不重复发布 |
| 压缩时会话删除、撤权或修改来源 | 旧候选不得发布，原始记录按权限读取 |
| 摘要超时、格式无效或程序重启 | 旧摘要与原文保留，状态可恢复 |
| 模型返回上下文超限 | 有界重试或明确失败，不能假装压缩成功 |
| 多次压缩后追问更正、数字和未完成事项 | 能回读原文并抽样核对 |
| 发票查询、授权写入与故障恢复 | 保持权限、事实来源、幂等和回执 |

这是实施计划，当前尚未实现。需通过实际模型、独立留出案例和人工复核确认可靠性，不能承诺所有语义都不会丢失。
