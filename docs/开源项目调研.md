# 开源 Harness 与现有 RSI 原型：财税赛题适配调研

研究日期：2026-10-25。对象为本地 `D:\rsi`（其 `.git/config` 的 `origin` 是用户给出的 `https://github.com/luyu020816-droid/rsi-personal-agent.git`，本地 `main` 为 `c14d1b421b41fb3cfd79e5abb053ca7399824afe`）、DeepSeek 官方 [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)、OpenAI 官方 [codex](https://github.com/openai/codex)。GitHub 上的用户仓库本次网页访问返回 cache miss，命令行 `git ls-remote` 因沙箱网络不可用，**无法核对远端是否与本地提交一致**。下面对 RSI 的代码级判断基于本地只读源码；DSH 与 Codex 基于官方仓库固定版本及官方说明，未运行性能或安全实验。

## 一、结论

**可以借用 RSI 的运行时和证据链，但现有代码不能直接作为本赛题成品。** 赛题需要模型在多轮中选择查询、追问、调用业务工具并核对写入，而 RSI 当前的模型请求明确给出 `tools: []`，DeepSeek 适配器只处理文本并拒绝工具调用；当前数据所有者硬编码为 `local`。这三处分别卡住工具闭环、模型工具协议和用户／企业隔离，优先级高于引入更复杂的插件系统。[本地 Context 源码](D:/rsi/backend/app/context.py#L28-L50)、[DeepSeek 适配器](D:/rsi/backend/app/deepseek_adapter.py#L1-L20)、[本地 Store](D:/rsi/backend/app/store.py#L1-L10)。

推荐路线：在 RSI 的 Session/Run、来源追溯、上下文与执行记录上做**财税领域的窄适配**；吸收 Codex 的“工具定义、执行器、权限与沙箱分层”，吸收 DSH 的“可替换能力接口、请求事件与执行前最终 guard”，但初赛不整合两个庞大运行时，也不把自进化实验作为主线。该取舍是针对赛题的设计判断，不是上游项目的官方建议。

实施形态建议用**独立赛事分支或独立项目**：选取上述模块及测试作为底座，另建财税业务表、可信用户／企业会话和规则库；不要把原 Personal Agent 的 `local` 所有者和个人记忆直接扩成财税权限系统。若直接在现有产品主线改造，单用户假设和现有前端会扩大联调范围。材料中的“一周左右”是工作量设计说明，实际截止时间尚未提供，不作为本报告的工期约束。

## 三、DSH 值得借的机制

固定研究版本：官方 [release `dsh-v0.2.1-alpha.3`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.3)，此前本地研究记录对应 commit `2fbf435`；本次重新打开了该 tag 的工具源码，并交叉看官方 `master` 架构说明。`master` 会继续变化，下面标明其证据类型。官方 [README](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.3/README.md) 明确仍为 developer preview，兼容性可能破坏。

1. **能力接口与实现分离。** DSH 把 agent loop、模型适配器、工具、会话存储等装为 Cordis 插件；其 [架构说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md#cordis) 和 [包地图](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/README.md#package-groups) 说明可替换服务、提供者和消费者的边界。财税项目只需先定义小接口：`InvoiceRead/Update`、`BankRead`、`RuleLookup`、`MemoryStore`，把固定业务实现放在接口后；初赛无须复制 Cordis 插件树。
2. **执行前的集中 guard。** 固定 tag 的 [工具执行源码](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.3/packages/core/tools/src/index.ts#L678) 有工具注册、执行前检查和拒绝路径。财税业务工具应在实际写入前重新验用户对企业的权限、票据版本、允许修改字段、当前取消状态，不能只信模型的意图或旧上下文。OS 沙箱与业务授权是两个边界。
3. **会话事件和模型视图分开。** [官方架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md#session-log) 区分持久 `SessionEvent`、可还原的模型历史、实时流。比赛运行记录可沿用“原始工具事实是权威、UI 是投影”的思路，便于回放错账、错规则和误报保存。
4. **一次请求绑定模型与工具上下文。** [官方架构的 turn flow](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md#turn-flow) 描述先准备调用、冻结请求再执行工具。财税场景要把本轮企业、月份、规则版本和工具 schema 固定成快照；写操作时重新校验当前授权与票据 revision。

DSH 的通用工作流、子代理、调度和动态装卸能力覆盖面广，[包地图](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/README.md#package-groups) 可见其规模。初赛核心是具体财税闭环，整合这些系统会引入大量配置、迁移和调试成本。官方预览状态也意味着版本锁定和接口核查不可省略。

## 四、Codex 值得借的机制

固定研究版本：官方 [release `rust-v0.162.1`](https://github.com/openai/codex/releases/tag/rust-v0.162.1)，commit `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`；本次重新打开固定提交的 [turn.rs](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/core/src/session/turn.rs) 和 [orchestrator.rs](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/core/src/tools/orchestrator.rs)。当前 `main` 的接口仍在演进，以下只作机制借鉴。

1. **Turn/Step 与工具结果回填。** [固定版 turn.rs](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/core/src/session/turn.rs#L442) 将模型采样、工具请求、结果回填、继续采样纳入同一轮。这是 RSI 当前 `understand → respond` 路径之外最急需的能力：模型能查询聚合，再依据实际工具结果答复；缺企业／月份时先追问。
2. **工具路由和权限分层。** [ToolRouter](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/core/src/tools/router.rs#L68) 管理模型可见定义与执行器匹配，[ToolOrchestrator](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/core/src/tools/orchestrator.rs#L119) 管理执行控制；[exec policy 源码](https://github.com/openai/codex/blob/main/codex-rs/core/src/exec_policy.rs) 展示 allow/prompt/forbidden 的独立决策。财税工具要把“模型提出动作”与“业务层准许执行”分离，所有金额计算与权限决策在代码中确定。
3. **执行快照、恢复和取消语义。** [StepContext 与工具并发](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/core/src/tools/parallel.rs#L41) 绑定本 step 工具环境；[rollout 恢复](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/core/src/session/rollout_reconstruction.rs#L173) 区分历史和检查点。赛题里的“保存用途后再次查询”必须以已提交数据库状态为准；取消不能抹去已经提交的修改，结果未知不能盲目重试。
4. **协议和可观测性。** Codex 以 core 供 CLI/UI 使用，[官方 core README](https://github.com/openai/codex/blob/main/codex-rs/core/README.md) 说明核心边界；[app-server 协议](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md) 包含线程、回合与事件。财税项目可设计较小的事件协议展示“模型决定调用什么、工具实际返回什么、如何组织最终回答”。

Codex Rust 内核和 DSH 插件整包都与各自会话、事件、配置、执行环境强耦合；对 Python/FastAPI 的 RSI，**直接搬运内部模块不划算**。Codex SDK 可以作为未来生成代码或评审 worker 的独立接入点，但初赛主链路应由自身业务工具和规则控制。两项目的源码许可证分别是 [Codex Apache-2.0](https://github.com/openai/codex/blob/main/LICENSE) 与 [DSH MIT](https://github.com/deepseek-ai/deepseek-harness/blob/master/LICENSE)；实际复制代码时应锁版本并保留许可声明。

## 六、比赛材料梳理与可核对的基线

本部分依据材料包 v1.1.0 的[参赛说明](./赛题二：财税Harness初赛材料包-v1.1.0/01_参赛说明.docx)、[业务规则](./赛题二：财税Harness初赛材料包-v1.1.0/03_业务规则.docx)和[示例数据](./赛题二：财税Harness初赛材料包-v1.1.0/02_示例数据.xlsx)。所有企业和规则均为模拟，不用于真实财税处理。

### 任务边界与评分

一个模型驱动的流程处理三类对话：①查询指定企业及月份的发票合计、银行收入／支出和适用填写要求；②按用户明确指令修改指定发票用途或备注，随后重查核对；③检查未填用途并在多轮及新会话中续办。模型负责理解、追问与选择工具；程序负责金额计算、数据约束、权限、规则筛选和持久化。不能以关键词分支或预写答案代替模型决策。

评分为基础任务完成度 40%、AI 技术应用合理性 25%、问题理解 15%、后续完善空间 10%、创新性 10%。初赛以基本场景和核心功能为主；复赛才增加长对话、未公开数据组合、规则变化和故障处理，具体要求另行公布。

| 对象 | 必须分开的状态 | 关键约束 |
|---|---|---|
| 业务数据 | 发票、银行流水、用户企业权限 | 当前保存结果是权威；Excel 是初始导入和核对基线。银行只读，发票只准改用途／备注。 |
| 规则知识 | 编号、名称、版本、企业、生效日期、状态 | 停用规则不能作为当前依据；回答注明规则名称与版本，支持导入、查找、更新、停用。 |
| 任务记忆 | 用户、企业、月份、待办、用户明确偏好 | 每个用户在每家企业最多一个未完成任务；支持查看、更正、删除；新会话能续办，但旧记忆不等于本轮修改授权。 |
| 运行证据 | 本轮模型输入、选用记忆和规则、工具调用及结果、最终答案 | 可供评委核对；不记录模型密钥。 |

规则要点：R001 1.0 将发票价税合计、银行收入、银行支出分别求和，金额用 Decimal 或整数分，显示两位小数；月份不明且上下文没有明确月份时追问。成功查询但无记录时回答 0.00 元并说明没有记录；无权限或查询失败不能写成零。R004 1.0 规定银行流水不与发票逐条对应，不能根据同额、日期或交易方推断已付款。R002 甲企业 1.0 已停用；2026 年 9 月应使用 2.0，所有发票均须有用途。R003 乙企业 1.0 要求金额**大于或等于** 1000.00 元的发票有用途。空白和纯空格均为未填；备注不能替代用途；销售方和票面项目不能被模型猜作实际用途。
