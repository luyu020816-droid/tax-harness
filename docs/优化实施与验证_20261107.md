## 实现范围

- 新增 request_checklist：对明确的月度查询、用途检查和规则解释形成企业/月度事项清单，独立核对交付。核对失败沿原有 REPLY_EVIDENCE_MISSING 反馈要求补办，不重新授权保存。
- 单纯只交付一个月不能覆盖用户明确要求的另一个月；无关企业的错误不能覆盖当前企业的漏办。
- 权限拒绝可由宿主逐企业实际检查，不强迫调用必然被拒绝的工具。无法执行须有相符的终止错误；错误参数、旧上下文等可修正错误不作为事项完成依据。
- 清单不建立第二套持久任务，也不授权修改。单张票据和明确序号不会被强制扩成月度用途检查；配对含糊的双企业双月份不做笛卡尔积。
- 新增持久化事项卡片，区分已核对、待补充、无法执行；有未完成事项时页脚显示“已反馈，含未完成事项”。任务反馈中的 active/waiting_user 转为中文。
- 仅对存在核对事项的请求附加简短提示，空清单不额外入模，避免无关保存流程增加固定上下文开销。
- README 当前状态和设计简述更新，历史报告继续保留各自候选边界。人工验收步骤见[验收清单](人工验收清单_20261107.md)。

本轮没有重做通用模型规划或多任务槽，没有开启语义检索，也没有修复所有历史检索失败。该有限核对机制不能证明任意自然语言需求全部识别；分页完整性、复杂条件和未覆盖表达仍须人工检查。清单“已核对”不是发票已经补齐，更不是保存成功承诺。

## 实模型与人工验收

最初自动审批拒绝执行六场景实模型脚本，理由是优化授权未明确涵盖向外部模型接口发送模拟财税资料。用户随后明确授权使用现有模型接口验证，再执行以下两轮；没有绕过审核，没有使用主业务库。

- v1：六场景各一次，5/6 自动通过。配对企业/月度查询在调用模型前以 SOURCE_INVALIDATED 中断，原因是当前原始消息关联两家已授权企业，却被范围依据读取当作精确单企业证据。失败原件保留在 `.local/evidence/checklist-live-20261107-v1/paired-scopes-run-1.json`，不能用成功重跑覆盖。
- 修复：仅当范围依据为本轮当前消息时，不再对整条原始消息施加单企业精确过滤；绑定仍要求本轮、本人、真实企业月份依据，read_source 仍核验归属和消息关联的全部企业权限。普通历史、工具、知识及其他来源的单企业读取边界没有放宽。
- v2：修复后同六场景各一次，6/6 自动通过；覆盖双月份、查询加规则、双企业正确配对、缺月份追问、不支持月份和权限拒绝。逐项检查工具轨迹，配对场景只查询甲八月、乙九月两组，没有执行四组笛卡尔积。原始轨迹与报告保存在 `.local/evidence/checklist-live-20261107-v2/`。
