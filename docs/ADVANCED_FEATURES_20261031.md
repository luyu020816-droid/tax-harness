# 四项官方加分能力：实现与复现

依据：[赛题二官网的 ADVANCED 四项](https://aicxds.yunzhangfang.com/challenge-02.html?v=20261016-6)。本次在 `feature_adjust_1031` 上补齐实现、固定样例和执行证据；不据此推算比赛得分。原有报告是历史记录，本文件与 `evals/advanced-v1/` 记录本批增量。

## 1. 长对话摘要保留信息与未完成事项

模型继续生成有来源的导航摘要。程序另从其全部来源中提取用户原话，按完整句子去重，保留否定、编号、更正和未完成事项。`summary_evidence.py` 校验来源、修订、作用范围、逐字内容与哈希，并重新提取比对，防止删掉一条摘录后仍被使用。助手旧答复不是事实保护依据；当前金额、规则和任务状态仍须读取正式状态。

摘要保存为 `extractive-summary-v1`，其中 `navigation` 是可能有损的模型叙述，`protected_excerpts` 是逐字证据。旧格式无此保护的摘要不会直接装入模型上下文，可由后续压缩重新生成。候选失败不会覆盖旧摘要或删除原文。

真实对比发现模型偶发将来源列表包成一层嵌套数组。现在仅归一化这一种无歧义的单层包裹，随后仍要求来源集合与实际输入完全一致；不补漏掉的 ID、不接受未知 ID、不递归展平。原始响应继续保留在轨迹中。

新增 `read_summary_source(source_id, quote)`：只能回读当前用户、当前企业、当前记忆版本的有效摘要所覆盖的摘录，并由历史证据存储签发可核验引用。最终展示仍走同一 `history_quote` 校验；不会因为内容来自摘要就放宽来源校验，也不能据此授权修改。

默认保护预算为 `SUMMARY_EVIDENCE_BUDGET=3000`，使用保守 UTF-8 长度估计，不是模型精确 tokenizer。放不下时拒绝发布候选、保留原文并允许检索。它没有承诺无限长度原话可压缩成固定长度且完全无损，也未证明导航摘要本身没有语义遗漏。

`probe_summary_coverage.py` 注入故意漏掉柜号和“不得外发”的摘要，验证导航仍有损、保护摘录保留原话。此程序测试不冒充真实模型质量测试。

## 2. 更正、规则更新、企业切换、数据修改后的正确性

每次输入都重新读取正式任务、偏好、企业选择、数据修订和规则版本。来源删除或更正使派生记忆失效；业务资料或规则改变使旧检查需要刷新。摘要不能覆盖这些正式状态。

新增连贯回归覆盖：记住并更正偏好；授权保存甲企业 F002 后缺项从 5 变为 4；切到乙企业检查仍为 3；删除偏好后正式列表为空；管理员将甲企业用途规则换到第 3.0 版、金额门槛 1000 元后，使用新规则检查，同时乙企业规则不变。规则变更使用管理员受控入口，聊天不能启用新规则。

真实模型固定样例另验证企业切换、保存后重新检查和规则换版，预期数量写在运行前固定的 `cases.json`。固定样例中的旧聊天记录是导入的模拟资料，未称为模型生成的对话。

## 3. 工具超时、进程重启后的恢复与去重

原有持久队列、租约、执行代次和 fencing token 继续使用。恢复执行开始时，宿主先查原来源的操作记录，调用 `get_invoice_operation` 回读保存状态，再把真实回执交给模型。核验也占用本轮工具预算并留下记录。源请求保持不变，因此已有保存仍使用原幂等身份。

新增 `POST /api/v1/turns/{turn_id}/retry`，参数是 `request_id`、`expected_generation`。只允许本人当前失败、错误属于超时/模型暂不可用/数据库暂不可用的轮次恢复；来源必须有效，权限重新校验。重复恢复请求不新建轮次；取消、完成、来源失效和旧代次不能借此恢复。旧执行凭据在排队时即失效。

工作台失败消息增加“核对结果并继续”。恢复仍受本轮时长、模型调用和工具调用预算限制；没有无限自动重试。

恢复答复必须交付真实 `operation`，不能再附上声称整轮未修改的 `no_changes`。对应校验会明确告知保留回执、仅删除矛盾说明，避免模型误以为需要再次查询或保存。

独立故障脚本真实终止本任务创建的子进程，覆盖 COMMIT 前中断、COMMIT 后中断和提交后回读断连。验证回滚或找回原回执、只存在一笔操作、发票修订只增加一次、旧 token 被拒绝。`--live-model` 让恢复后的答复使用真实配置模型；故障边界仍由程序控制，不依赖模型猜时机。缩短总时限的超时注入在后端回归中覆盖。

## 4. 记忆、检索、输入方式的可控对比

新增 `evaluate_advanced.py` 与 `evals/advanced-v1/cases.json`。同一模型、同一问题、同一业务初始资料和相同权限/保存/引用校验下比较：

- `window`：近期两轮，不使用摘要或历史搜索。
- `summary`：近期两轮加摘要，允许从摘要回读原文，不进行全库历史搜索。
- `summary_search`：近期两轮加摘要，并允许历史搜索。

三策略都保留正式任务、偏好和业务状态。生产默认仍为近期 12 轮、启用摘要、自动压缩和历史搜索；实验通过明确配置关闭某些输入能力，不关闭安全校验。实验禁用自动压缩，摘要在固定位置准备，避免隐含触发条件造成比较漂移。

每个样例、策略、重复次数使用一个新数据库；输出目录不可覆盖，数据库存在即拒绝复用。不重置用户业务库。顺序轮换降低单一先后顺序影响，但不能消除网络和服务端缓存差异。

固定断言核对实际引用中的关键字、当前企业、缺项数量、规则版本与写操作数量；不让另一个模型主观打分。记录逐次请求的实际 provider usage、耗时、输入哈希、工具调用、实际检索模式及完整上下文轨迹。摘要准备、失败、重试和修复调用计入；数据库初始化、导入模拟资料的耗时不计入请求耗时。

`correct` 是包含摘要准备在内的全流程门槛；`answer_correct` 单独表示最终答复是否满足固定事实断言。摘要失败后靠检索答对，会表现为前者失败、后者成功，不隐藏中间失败。

费用依据 [DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/) 的 2026-10-31 价格快照，按同一非高峰价格归一化估算，使用实际缓存命中/未命中 token。它不是账户实付账单；不计本地 CPU、存储和网络费用。未返回 usage 或模型与价格快照不匹配时记为未知，不计作零；缺缓存拆分时给出全未命中的上界估计。

本地未安装真实 BGE 权重时，检索模式按实际 `lexical_only` 记录，不能据此声称比较了向量检索。该开发集只有六个固定样例，不能据此证明统计显著性或未见数据泛化能力。

## 复现

在项目根目录、已配置 `.env` 和项目 PostgreSQL 的 PowerShell 中运行。模型比较与 `--live-model` 会使用已配置模型产生调用费用。仅做程序验证时不需要模型 Key。

```powershell
.\.venv\Scripts\python.exe -m pip install jieba==0.42.1
.\.venv\Scripts\python.exe scripts/probe_summary_coverage.py --output .local/bonus-summary-new
.\.venv\Scripts\python.exe scripts/verify_advanced_recovery.py --output .local/bonus-recovery-new
.\.venv\Scripts\python.exe scripts/verify_advanced_recovery.py --output .local/bonus-recovery-live-new --live-model
.\.venv\Scripts\python.exe scripts/evaluate_advanced.py --output .local/bonus-comparison-new --runs 3
```

数据库名称以 `tax_harness_bonus_` 开头，来源于输出目录摘要；脚本不自动删除这些证据库。原 `probe_summary_coverage.py` 复用已有的检索评测隔离库创建器，同样不触碰业务库。故障脚本临时凭据只存于忽略的本地目录，结束后删除该文件。

程序回归可在 `backend` 运行 `..\.venv\Scripts\python.exe -m pytest`，不要与原 `scripts/evaluate.py` 同时运行，因为后者会重置共享测试库。新的三策略比较使用各自独立数据库，可以与程序回归并行。

完整向量协议回归需要先按[既有运行环境说明](PATCH002_KNOWLEDGE_RUNTIME.md)安装 pgvector；真实 BGE 推理还需要对应权重与 Torch。本批策略对比使用实际可用的词法路径，未安装完整 BGE 权重。

本批执行结果见 [验证记录](ADVANCED_VALIDATION_20261031.md)。未解决的原生推理崩溃根因、任意多意图完整识别、人工语义签收及提交录屏仍按原 TODO 管理，不能因加分能力实现而一并关闭。
