## 2. 背景与目标

### 2.1 赛题对应要求

| 编号 | 复赛要求 | 本阶段必须交付的可观察行为 |
|---|---|---|
| R-01 | 通过配置动态管理不同职责的 Agent，含提示词、模型和能力权限，无需修改或复制代码 | 从作品原入口新增、修改、启停和选择 Agent；不同 Agent 可配置不同职责、模型配置和能力授权 |
| R-02 | 控制配置变更生效范围，多个 Agent 职责和权限隔离 | 显示运行所用版本；区分新请求、运行中请求及安全撤权；越权工具调用被执行层拦截 |
| R-03 | 按任务组织、组合和复用 Skill、Tool 与知识，管理版本与启停 | 一个已有能力可供多个 Agent 使用；一个 Agent 可配置多个能力；Skill 组合及知识范围可配置、版本化和启停 |
| R-04 | 变更影响、未授权调用、停用后行为清楚 | 界面和日志显示状态、版本、拒绝原因；停用或撤权后不能继续调用或提交未完成操作 |
| R-05 | 原入口可配置 Agent、能力及知识，切换用户、企业和会话，并可查看执行记录与模型实际输入 | 不以仅有命令行、源码或演示页面替代真实入口；保留现有身份、企业、知识和运行记录入口 |

### 2.2 问题

当前作品已有真实模型对话、财税工具、知识检索、企业权限与运行追溯，但当前主要围绕一个统一助手组织。现场评委需要无需复制代码，通过配置创建不同职责的 Agent，并验证能力共享、版本、启停及权限隔离。仅改变界面名称或提示词不能满足要求。

### 2.3 目标

- 保留现有业务、权限、知识、任务、回执和上下文机制，增加可配置的 Agent 与能力层。
- 在原工作台配置并使用至少两个职责不同的 Agent，且具备不同模型配置和不同能力集合。
- 一个 Tool 可被多个 Agent 在各自授权下复用；Skill 可组合已有能力；知识范围可被多个 Agent 配置使用。
- 每次模型请求前筛选能力，在每次实际调用和重要副作用提交前重新核对；变更、停用和撤权的生效规则可验证。
- 现场能从实际数据、运行记录和模型输入核对配置、权限、执行与最终答复。

### 2.4 不在第一阶段范围

- 通用 Excel 表格解析、复杂金额分析：属于下一阶段；保留现有固定发票模板导入。
- 从零重写长期记忆、上下文压缩、多轮任务引擎或故障恢复；本阶段仅完成与 Agent 配置相关的必要适配和回归。
- 自动多 Agent 规划、自动委派或多个模型互相对话：本阶段支持多个 Agent 共存和用户选择；不宣称自动协作已完成。
- 运行时上传并执行任意代码、第三方插件市场、任意自定义 Python 工具。新增 Agent、Skill 组合及既有能力授权无需改代码；新增可执行工具实现仍需开发与注册。
- 真实生产认证、多租户 SaaS 与高并发容量。本作品现有登录是比赛模拟身份，不能包装成生产级身份认证。

## 4. 术语与权限边界

| 术语 | 定义 |
|---|---|
| Agent | 一组可配置的职责提示、模型配置引用、能力授权及知识范围；不是独立用户或企业身份 |
| Tool | 已在宿主注册、由程序执行的具体能力；包含参数契约、动作范围和实现版本 |
| Skill | 可版本化的任务指引及其依赖能力集合；指引是辅助模型执行的配置，不能自行授予权限 |
| 知识范围 | 可被 Agent 使用的知识集合或文档范围，仍受当前用户、企业、资料状态及有效版本限制 |
| 配置版本 | 保存一次发布的完整配置及其关联能力版本，用于运行追溯；不是当前权限的永久授权 |
| 模拟管理权限 | 本地比赛环境中允许操作配置的显式权限；不是生产管理员认证 |
| 原入口 | 实际连接后端的作品工作台，非 `frontend/demo.html` 的概念演示 |

**有效权限** = 当前用户对企业和资源的权限 ∩ 当前 Agent 被授予的动作和知识范围 ∩ 当前能力、Agent、资料状态 ∩ 业务所需的用户明确授权和确认。

平台安全规则、业务规则和服务端权限优先于 Agent 提示词、Skill 指引、用户消息和文件内容；任何配置均不得绕开原有授权、写入校验、来源校验或金额计算。

## 5. 用户角色与入口

### 5.1 角色

- **配置管理者**：可在本机作品原入口管理 Agent、模型配置、Skill 和能力启停；对敏感配置操作必须由后端校验明确的模拟管理授权。建议样例 U001 有配置管理权，U002 无，实际初始化和迁移必须显式设置，不从显示名称推断。
- **普通使用者**：可选择被允许使用的启用 Agent，在自身用户／企业授权范围内对话、读取结果和操作；不能通过伪称管理员更改配置。
- 模拟登录不等于安全生产认证。配置管理入口还应沿用本机、同源和请求校验等现有边界，且不能仅依靠界面隐藏按钮。

### 5.2 原入口

1. 工作台提供当前 Agent 选择器，显示 Agent 名称、职责概述及启停／模型可用状态。
2. 配置管理者能进入 Agent 管理、能力目录／Skill 管理和模型设置，并从原入口进入现有知识管理。
3. 用户可继续切换用户、企业和会话；Agent 选择与这些边界独立，切换不增加任何用户或企业权限。
4. 在运行详情中可查看 Agent、配置版本、能力、工具调用及实际模型输入；内容访问仍受原有用户与企业权限约束。

## 6. 产品需求

### 6.1 Agent 管理

**AG-01 创建与编辑。** 管理者可新建、查看和编辑 Agent：名称、职责说明、职责提示词、模型配置引用、允许的 Tool 动作、Skill 与知识范围。名称供识别，不作权限标识；内部使用稳定 ID。创建、编辑和发布不复制代码。

**AG-02 草稿与发布。** 编辑产生草稿；发布时验证模型引用、工具动作、Skill 依赖和知识范围均存在且配置合法。发布生成不可变版本。名称重复、引用不存在、依赖不满足或版本冲突时拒绝发布并指出原因。编辑页面展示当前生效版本与草稿状态。

**AG-03 启停。** 启用的 Agent 才能接收新请求；停用后选择器标注不可用，不接受新请求。已运行的请求按第 8 节处理；历史记录保留。第一阶段不提供物理删除，避免破坏历史引用。

**AG-04 用户选择。** 每条新用户请求在服务端接收时绑定用户所选 Agent ID 和已发布版本，并写入请求记录。会话可在不同轮次切换 Agent；历史消息保留各自 Agent 标识。切换只影响后续新请求，不自动接管另一 Agent 的运行或待确认操作。

**AG-05 职责与权限隔离。** 对模型只提供该 Agent 当前允许且本轮适用的工具；工具执行时再次检查。Agent 的职责提示词不得更改系统安全指令、冒充其他身份或改变用户／企业权限。

**AG-06 初始配置。** 初始化提供「财税办理 Agent」与「知识查阅 Agent」两个可编辑示例；前者在用户本身有权且操作获得明确授权时可办理发票，后者没有发票修改及导入提交能力。示例不意味着其他账号自动获得企业权限。

**AG-07 Agent 选择权限。** 第一阶段启用的 Agent 可供当前已登录模拟用户选择；Agent 内的能力仍受用户、企业、知识范围等交集限制。若未来需要限制某些用户看见或选择某 Agent，另行扩展，不用名称或提示词假装实现。

### 6.2 模型配置

**MD-01 多配置。** 支持多个模型连接配置，每个 Agent 可引用一个；至少可配置两个不同模型名或供应商地址，并分别测试后用于不同 Agent。测试失败不能覆盖原有可用配置。

**MD-02 密钥。** 配置元数据可持久化；密钥不出现在前端存储、普通日志、模型输入快照、运行记录或提交包。第一阶段页面录入的密钥仅保存在服务进程内，重启后相应连接显示待配置并需重新输入；已有 `.env` 默认连接按现有方式恢复。界面必须解释该行为，不能在缺密钥时悄悄切换其他模型。

**MD-03 运行绑定。** 请求开始时绑定模型配置版本和当时可用连接；编辑模型配置不改变已开始请求。若服务重启或连接不可用，恢复过程如实标记不可用，不能静默替换为另一模型。每次实际模型请求记录可公开的配置 ID、版本和模型名，不记录密钥。

### 6.3 能力目录与 Tool

**CP-01 目录。** 工作台列出宿主已注册的 Tool，显示稳定 ID、名称、用途、实现版本、支持动作、启停状态和风险类型（只读／产生业务或配置副作用）。列表来自服务端注册信息，不把任意未注册工具显示为可调用。

**CP-02 授权。** 管理者可在 Agent 配置中选择允许的工具及必要的动作；未明确授权默认拒绝。对 `manage_preference` 等同一工具包含读取与修改的情况，须按动作区分，不能把读取授权扩大为写入授权。

**CP-03 复用。** 至少同一个发票查询 Tool 可被两个 Agent 分别引用；共享实现但不共享运行身份、企业范围、会话、结果或授权。

**CP-04 别名与间接路径。** 授权以实际目标能力和动作判断；例如 `lookup_knowledge` 必须按其最终路由到的规则或知识检索检查。工具间接调用及多动作参数不能绕开检查。对无法确定真实目标的请求默认拒绝。

**CP-05 启停与版本。** 管理者可启停已注册能力；停止后的新调用和未提交的相关副作用必须被阻止。工具实现版本只指宿主真实存在、可运行的版本；不能仅改标签假称实现已换版。第一阶段可发布目录配置版本；若没有多个已注册实现，不提供虚假的实现版本切换。

**CP-06 配置效果。** 授权增减、能力启停、Skill 变更和知识范围调整在发布前显示影响的 Agent；若被其他启用的 Agent 引用，不以隐藏依赖或静默扩大授权的方式处理。

### 6.4 Skill 组织与复用

**SK-01 数据组成。** Skill 包含稳定 ID、名称、用途、任务指引、依赖的工具动作／知识范围、版本和启停状态。指引不得包含凭据或覆盖平台安全约束。

**SK-02 创建组合。** 管理者可通过界面创建或编辑由已有工具动作和知识范围组成的 Skill；可以被多个 Agent 引用，同一 Agent 可配置多个 Skill。例：「发票核对 Skill」依赖查询和规则读取；「制度问答 Skill」依赖知识检索与引用回读。

**SK-03 权限不提升。** 挂载 Skill 不自动授予工具或资料权限。只有 Skill 依赖、Agent 显式授权、当前用户／企业授权和能力可用状态同时满足，相关动作才可用；依赖缺失时发布校验指出缺口。Skill 不能执行未注册代码。

**SK-04 版本及停用。** 编辑并发布产生新版本；停用后新请求不加载该 Skill 指引或作为可用 Skill 展示。仅因某 Skill 停用，不自动禁用 Agent 直接授权的其他 Tool；若具体任务仅依赖该 Skill，应提示改用其他已授权方式或无法执行。已有历史版本可审计。

### 6.5 知识能力

**KN-01 配置范围。** Agent 配置支持选择「无知识」「用户当前有权访问的知识」或「指定知识集合／文档」。默认无知识；所选范围不是数据授权，最终仍须通过用户、企业、资料状态和版本检查。

**KN-02 按需使用。** 只向已授权且启用检索能力的 Agent 暴露知识工具；搜索、原文回读及引用呈现均限制在该 Agent 范围内。不存在或无权访问时如实说明，不泄露标题或内容。

**KN-03 变更。** 知识原有更新、发布和停用机制继续生效；资料撤权、停用或换版后，运行时不得继续将失效资料作为有效依据。需要清理已装配上下文或阻止旧上下文继续发送和提交，具体以第 8 节处理。

**KN-04 第一阶段边界。** 复用现有知识管理入口和已支持格式；不把当前固定模板 Excel 导入宣传成通用知识 Excel 查询。本阶段需要能从原入口配置知识与 Agent 的关联；现有仅命令行才能完成的必需配置须补可操作入口或在第一阶段明确实现。

## 7. 配置与运行流程

### 7.1 管理者配置

1. 在模型设置中分别配置、测试两个模型连接；不要求两个 Agent 必须使用不同供应商。
2. 在能力目录查看 Tool，创建两个 Skill 并配置依赖。
3. 创建或编辑两个 Agent，分别填写职责、选择模型、授权 Tool、关联 Skill 和知识范围。
4. 发布时校验引用、依赖和并发版本，成功后显示版本号与生效说明。
5. 在原工作台选择 Agent 发起真实请求；在运行详情核对模型输入和执行结果。

### 7.2 用户发起一轮请求

1. 后端验证登录、会话、用户／企业授权及 Agent 可用状态，绑定 Agent 发布版本与模型配置版本。
2. 根据 Agent 显式授权、Skill 状态、现有企业权限和当前资源状态生成本轮可用能力集合；不把未授权工具定义发给模型。
3. 组装平台不可覆盖规则、Agent 职责、已启用 Skill 指引、当前任务和必要上下文；保留现有来源与预算检查。
4. 每次调用前解析实际目标并重新检查当前权限和状态；写操作保留现有准备、确认、幂等和提交校验。
5. 从真实工具结果和数据产生答复；记录配置版本、调用、拒绝、实际模型输入和结果。

### 7.3 示例能力矩阵

| 能力 | 财税办理 Agent | 知识查阅 Agent | 额外约束 |
|---|---|---|---|
| 发票查询 | 可配置允许 | 可配置允许 | 当前用户必须有该企业读取权限 |
| 正式规则查询 | 可配置允许 | 可配置允许 | 规则和企业范围校验 |
| 知识检索及引用 | 可配置允许 | 可配置允许 | 当前 Agent 范围与用户资料权限同时满足 |
| 发票修改准备／提交 | 可配置允许 | 默认不允许 | 用户企业写权限、明确授权、计划／确认及当前能力状态 |
| 任务／偏好管理 | 按具体动作配置 | 按具体动作配置 | 不因可读而获得更改权限 |

此表为初始化建议，不是可绕过后台校验的硬编码业务分支。

## 8. 版本、生效、并发和恢复规则

| 变更 | 新请求 | 已接收／运行中的请求 | 待确认与恢复 |
|---|---|---|---|
| 发布 Agent 新提示词、模型或增加能力 | 使用新发布版本 | 保留已绑定版本；不在一次模型运行中静默切换配置 | 原请求追溯原版本；不能因为新版本扩大权限而补授权 |
| 撤销 Agent 的工具动作或知识范围 | 新请求按新授权 | 下一次模型发送、工具调用及副作用提交前重新校验；旧上下文含已撤权内容时阻止继续发送并提示重新发起 | 相关待确认不得借旧配置提交；用户仍可查看其有权访问的既有回执 |
| 停用 Agent 或 Tool | 禁止新请求／新调用 | 阻止后续调用及未提交副作用；已提交操作如实保留和交付回执 | 不自动重新启用或改用其他 Agent；提示处理状态 |
| 停用 Skill | 新请求不加载该 Skill | 后续模型发送前重新核对；需移除失效指引或终止并提示重新发起 | 已绑定历史版本保留；直接授权的其他 Tool 不自动停用 |
| 模型配置变更 | 新请求使用新版本 | 已开始请求保持绑定配置 | 重启后密钥不可用须提示，禁止静默替代模型 |
| 知识停用、换版或用户撤权 | 只使用当前有效授权资料 | 阻止继续发送含失效资料的旧上下文；需要时重新检索 | 旧引用按现有权限和失效规则处理，不伪称仍有效 |

**并发安全：**配置修改必须带预期版本，冲突返回可理解提示，不能静默覆盖。能力撤权／停用与业务提交必须通过同一事务边界或等效锁／版本栅栏保证：撤权先生效则提交被拒；提交先完成则记录真实完成并保留回执。不得仅在界面或提交前很久检查一次。

**已发出的模型请求：**无法收回已发送给供应商的输入。之后必须阻止受撤权影响的进一步发送、工具调用和未提交写入，并如实记录状态；不承诺撤回已外发内容。

## 9. 界面和交互要求

| 页面／位置 | 必须支持 | 关键反馈 |
|---|---|---|
| 工作台 | 选择 Agent；展示当前用户、企业、会话和 Agent | 停用、模型未配置、能力不可用时显示明确状态 |
| Agent 管理 | 列表、创建、编辑、草稿、发布、启停 | 显示职责、模型、授权摘要、版本及变更影响 |
| 能力与 Skill | 查看 Tool；创建／编辑 Skill，配置依赖、版本和启停 | 未注册能力不能选择；缺依赖、被引用及停用影响清晰 |
| 模型设置 | 创建、测试、启用多个模型配置 | 测试失败保留原配置；密钥不回显；重启后的可用性明确 |
| 知识管理 | 从原入口查看或配置 Agent 可用的知识范围 | 资料无权、停用、换版和未就绪状态清晰 |
| 运行详情 | 展示 Agent、配置版本、能力、模型请求、调用与拒绝 | 只展示当前用户有权查看的内容；不暴露凭据 |

管理 API 的每个变更均做服务端身份、模拟管理权、本机同源和版本校验；不能只隐藏前端按钮。Agent 发起的发票计划及其确认／提交链路必须绑定来源 Agent 和授权上下文；在实际确认和提交处再校验。通过现有独立页面由用户自行发起的业务流程保留原有权限模型，界面须区分来源，不能借用 Agent 名义绕过检查。

## 10. 数据与接口要求

以下是逻辑实体，不要求直接采用表名；具体数据库迁移和接口契约在技术设计中确定。

- Agent：稳定 ID、状态、当前发布版本、创建／更新时间。
- Agent 版本：职责提示、模型配置版本引用、显式 Tool 动作授权、Skill 版本、知识范围、发布人和时间。
- 模型配置：ID、名称、非敏感连接元数据、版本、测试状态和进程内密钥引用；持久层无明文密钥。
- Tool 注册：稳定 ID、实际实现版本、参数／动作契约、状态与风险类别。
- Skill 及版本：指引、依赖能力、关联知识范围、状态和变更记录。
- 权限与变更：模拟管理授权、发布／启停／撤权事件、操作者、时间及前后版本。
- 运行关联：用户、企业／会话、Agent 版本、模型配置版本、实际可用能力、工具调用和结果引用。

配置发布、启停和运行执行应有稳定请求标识、并发版本检查和可审计的结果；必要时复用现有请求去重，不能重复提交业务副作用。模型输入快照仅对实际有权查看内容的用户可见；敏感凭据及不再有权访问的资料不回显。

## 11. 错误与反馈

| 情况 | 必须行为 |
|---|---|
| Agent 未发布或停用 | 拒绝新请求并指出当前不可用 |
| 模型未配置、测试失败或重启后密钥缺失 | 指出模型不可用，不伪造结果、不切换其他模型 |
| Tool 未授权、停用或动作不允许 | 服务端拒绝，记录实际拒绝原因；不发生副作用 |
| Skill 依赖缺失或已停用 | 发布校验阻止无效配置；运行时如发生变更则如实提示 |
| 选定知识不存在、撤权或停用 | 不泄露无权内容，不以旧引用冒充当前依据 |
| 配置同时编辑 | 拒绝过期版本并提示刷新；不得覆盖别人刚发布的配置 |
| 运行中撤权或停用 | 中止受影响的后续发送、调用和提交；区分已完成、未完成、待核实 |

## 12. 迁移和兼容

1. 升级前记录源码、配置与数据库版本并完成一致备份；迁移在隔离库验证，不重新导入或覆盖用户现有业务数据。
2. 为现有系统建立默认 Agent 及默认模型引用，尽量保留原工作流；必须核对默认能力清单与原先真实行为，避免无意扩大权限。默认迁移结果需人工可见并可编辑。
3. 旧会话和旧运行没有 Agent 元数据时标为「历史默认助手／版本未知」，不虚构历史模型、权限或配置；旧数据仍遵循现有访问权限。
4. 已有 `.env` 模型作为默认连接；额外页面配置的密钥仅在进程内，重启后按 MD-02 处理。
5. 保留历史任务、资料、引用、工具回执及工作区未提交修改。迁移失败时停止升级、保留可恢复备份并说明状态；不在业务库上尝试破坏性回滚。
6. 保持原有模拟用户、企业权限、知识问答、写入确认、会话和运行追溯的回归。

## 13. 验收矩阵

每项必须记录代码版本、配置、模型／测试模式、输入、期望、实际结果、数据与日志证据；不得把模拟模型测试写成真实模型验证。

| ID | 场景与操作 | 必须满足 |
|---|---|---|
| AC-01 | 管理者从原入口创建两个 Agent，配置不同提示词及两个可独立测试的模型配置 | 不改代码；两个配置可保存、发布、选择；模型请求记录对应模型 |
| AC-02 | 编辑一个 Agent 提示词后发布 | 新请求使用新版本，运行中请求仍可追溯旧版本，另一个 Agent 配置不变 |
| AC-03 | 两个 Agent 共享发票查询工具 | 同一实现被复用；各自调用以当前用户、企业权限为准 |
| AC-04 | 只读 Agent 构造写工具调用、别名或不允许的动作参数 | 服务端拒绝、无业务数据变化、记录拒绝；不能只依赖界面或提示词 |
| AC-05 | U002 或无企业权限用户声称管理员并查询／修改越权企业 | 拒绝配置管理或企业访问，不泄露数据，不放宽业务权限 |
| AC-06 | 创建一个 Skill 供两个 Agent 复用，另一个 Agent 组合两个 Skill | 指引及依赖可见；不复制代码；未显式授权的依赖不能被调用 |
| AC-07 | 停用 Tool，再请求调用；恢复启用后再调用 | 停用时阻止，启用后仍需满足所有其他权限；日志显示生效状态 |
| AC-08 | 停用 Skill，但同一 Tool 仍被 Agent 直接授权 | Skill 不加载；Tool 不因 Skill 停用被错误地全局禁用 |
| AC-09 | 同一知识资料配置给两个 Agent；取消其中一个的范围或停用资料 | 当前可用范围内正常引用；被取消或停用后不得检索或回读作为有效依据 |
| AC-10 | 模型配置测试失败、服务重启 | 失败不覆盖原可用配置；页面密钥失效时明确提示，不静默切换 |
| AC-11 | 写入前并发撤销能力／停用 Agent；另测先完成写入再撤权 | 前者不能提交；后者保留唯一已完成回执，不重复修改 |
| AC-12 | 从 Agent 发起写计划后撤权，再尝试页面确认和提交 | 确认／提交链路拒绝；数据库不发生未授权修改 |
| AC-13 | 切换用户、企业、会话和 Agent，查看历史及运行详情 | 每轮显示正确 Agent 版本；当前权限外的模型输入、文件和业务内容不泄露 |
| AC-14 | 对现有业务库的隔离副本迁移 | 数据、原会话和写入／知识流程保留；旧记录不伪造 Agent 元数据 |
| AC-15 | 并发编辑同一配置并发布 | 过期版本被拒绝，成功发布版本完整可追溯 |
| AC-16 | Agent 或知识撤权发生在一次模型响应之后、下一次发送之前 | 不再次发送失效内容；阻止相关工具和副作用，如实显示状态 |
| AC-17 | 配置管理及模型设置使用非管理账号或非本机／非同源请求 | 后端拒绝；仅隐藏按钮不能算通过 |
| AC-18 | 普通用户使用原有独立发票导入或确认页面 | 原有用户／企业／确认校验继续生效；Agent 发起的计划不能绕过 AC-12 |

### 13.1 必需验证层次

1. **服务端自动测试**：配置版本、权限交集、别名／参数动作、并发撤权与提交、旧数据迁移、密钥不泄露。
2. **接口与真实数据库测试**：执行层拦截、知识权限、确认链路、事务竞争及数据不变性。
3. **原入口浏览器测试**：真实配置、Agent 切换、知识关联、日志和模型输入展示。
4. **真实模型测试**：至少两种职责分别完成授权任务、拒绝越权；保留每次实际输入、工具与答复。模型不主动尝试越权不代表拦截通过，还要执行程序构造的反例。
5. **回归**：现有财税查询、授权写入、知识问答、上下文、会话、操作回执及历史权限。

## 14. 第一阶段交付物与完成定义

- 可运行的原入口：Agent、模型、Skill／能力及知识范围可配置，用户可切换 Agent。
- 至少两个真实可用的 Agent，至少一个共享 Tool、一个可复用 Skill 和一组可配置的知识范围。
- 不同模型配置可分别测试和绑定；模型不可用不伪造成功。
- 运行记录能核对 Agent／模型／能力版本、实际模型输入、工具结果、拒绝和业务回执。
- AC-01—AC-18 按适用环境逐项执行并记录；失败保留，修复后复测；未测试不得标记通过。
- 迁移和回归通过；提供启动、配置、现场验收及已知限制说明。
- 同步更新根目录复赛 `作品使用说明.md` 的第一阶段操作路径；最终提交包与视频在后续统一完成。

## 16. 待详细设计解决的问题

- 在现有表与权限模型下，配置版本、授权 epoch 和业务提交如何实现同事务一致性，尤其是独立导入角色及确认链路。
- 将当前模型调用转换为多配置时，执行中的模型适配器与异步任务如何绑定、释放和恢复；不得改变 MD-02／MD-03。
- 现有工具的精确动作清单、别名及间接入口逐一盘点；遗漏时默认拒绝，不能直接授予整个通配集合。
- 知识集合如何映射已有个人／企业资料、版本和引用权限；撤权后旧模型输入的可见性与失效处理需与现有权限守卫一致。
- 用现有测试资源构建稳定的事务竞争与真实模型案例，确保记录失败与环境限制。

这些是实现设计待定项，不表示可以弱化本文中的功能或验收要求。
