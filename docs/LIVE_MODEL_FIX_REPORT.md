# DeepSeek 接入问题修复与验证

日期：2026-10-28。针对首轮真实模型测试暴露的问题进行修复，未改动原冻结案例 `evals/holdout-v1.json`，未修改日常工作台的发票数据。

## 修改内容

1. 历史检索的可选企业参数在 schema 与业务函数中保持一致，省略企业时不再触发 TypeError。
2. 一次模型返回多个工具调用时，完整调用与结果组使用本轮工具执行后的记忆版本。继续检查来源修订、业务数据版本和权限；外部并发更正/删除仍使旧执行失效。
3. 查询工具检查本轮明确指定的企业，不允许以有权限的另一家企业代替用户指定的企业。
4. 模型最终答复必须声明本轮偏好操作与结果；声明已提交时，程序核对当前来源对应的已提交操作记录。提示词明确要求先保存再确认，避免仅口头答应。
5. 偏好键增加 schema 格式约束；更正/删除失败后返回当前用户可见的准确对象与版本，供模型纠正重试，不自动模糊匹配或替换对象。
6. 最终答复增加状态与追问字段的交叉校验，采用标准 JSON 输出模式，并将实际字段错误及未交付的候选答复反馈给模型。受控修复最多两次，仍受原有总步数、工具数和时间上限约束。
7. 离线导入测试显式关闭模型配置，不依赖开发者本地是否配置密钥。
8. 补充逐轮评测断言，覆盖原评测漏掉的未持久化偏好、错误企业、中间失败和组合查询重复工具调用。补充文件独立于冻结案例，报告记录其指纹。

回复提示也收紧了重复清单、内部字段和超出比赛模拟范围的建议。
