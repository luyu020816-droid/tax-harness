**不能签署八项全部通过。** 本轮在获得扩展授权后使用本机配置的 `deepseek-flash`、隔离 PostgreSQL 和人工模拟资料补验。多轮办理、知识生命周期、工作簿计算和进程恢复的所测主流程通过；发现真实模型下的摘要格式兼容问题和能力停用后的回复失败，另观察到记忆偏好未体现在最终月度回复中。上一轮窄屏轨迹返回问题仍未修复。

基线仍为 `feature_adjust_1120` / `6ea63e0e9df73928d99f53750f6e4fad59c86e9f`。本轮没有修改产品代码；仅维护验收脚本的接口模拟、按钮定位和处理等待时间。原报告的 668 项后端通过、1 项跳过仍有效；真实模型补验是独立证据，不将这些场景混加成一个通过率。

## 八项结果

1. **Agent 管理：所测配置与查询通过，不能覆盖全部现场行为。** 两个不同职责 Agent 的月度/发票查询已通过；本轮另配置两名 Agent 共用 Skill，各自使用真实模型查询成功。配置和发布通过实际服务函数执行，不是本轮全部由浏览器操作。

2. **能力组织与复用：共享及恢复通过，停用后的用户回复未通过。** 同一 Skill 被两名 Agent 复用；停用 `query_month` 后，实际模型 schema 中没有该工具，没有执行越权查询；恢复后新请求查询成功。但停用时该轮最终 `status=failed`、`error.code=MODEL_PROTOCOL_UNSUPPORTED`、`final_message=null`。权限边界通过，不等于可用性通过。

3. **多轮办理：所测真实页面流程通过。** 使用作品原入口，先缺月份追问，再补 2026 年 9 月；局部保存 F002、更正 F002、保留 F003、取消剩余待办、回查两次保存回执。注入请求/确认响应丢失后，从页面按原请求核对，确认未重复保存。证据：`live-purpose-v2.log` 和 `live-purpose-v2-artifacts/`。

4. **长期记忆：六项持久状态与实际模型输入检查通过，最终回复个性化有限制。** 管理接口保存偏好，关闭连接池并重建 Database/Runtime，新会话的实际模型输入仍含有效偏好；覆盖后只含新值；企业偏好在相应企业覆盖个人偏好，切企业恢复个人值；U002 在其可读企业中不含 U001 偏好；删除后实际输入不含该偏好。六轮均完成。这里测试了重建运行实例，不宣称已完成“保存偏好后杀整个服务进程再从原页面恢复”的闭环。详细/简洁/适中虽然正确进入输入，最终月度查询回复相同，不能据此宣称偏好已在最终回复中生效。证据：`live-memory/report.json` 和逐轮 turn/trace。

5. **知识库策略：所测八个生命周期检查点通过。** 普通聊天不自动入库；同会话上下文可用；新会话不凭空回忆普通聊天；草稿不自动发布；明确提交并真实本地索引后可跨会话引用；新版编号从 `KH…` 切到 `NEWKH…`，实际输入和回复均使用新版；停用后同会话的新输入排除旧编号及引用，回复明确表示没有足够资料。真实检索/重排与生成模型均参与。证据：`live-knowledge-v2/`。该脚本后续记忆阶段最初因使用别名 `reply_style` 而不是规范键 `response_style` 的断言失败；这不推翻此前八项知识断言。另有独立记忆脚本完成六项检查，分项汇总见 `live-reviewed-summary.json`。

6. **文件处理：两组真实页面场景通过。** 标准列头：10 月实付合计 617.00 元，交通费 180.00 元，包含负数；更正为 11 月交通费 88.50 元；原表行/单元格定位可见。V2 后 10 月总额变为 717.00 元，旧引用按版本规则失效；停用后依据不可用。重排的受支持别名列头另得 10 月 32.60 元、交通费 12.40 元、11 月交通费 14.50 元，定位到 B 列。覆盖重复上传复用、下载链接、换版和停用。证据：`live-workbook-v2.log` 与截图/trace。此前 Word、文字型 PDF 的页面上传/处理/原件字节核对仍有效，本轮没有补做这两种格式的复杂自然语言计算题。

7. **上下文管理：未通过完整真实模型场景。** 12000 输入预算低于基础指令和工具定义占用，正确拒绝，本条属于测试预算前提不足。28000 预算、12 轮合成长历史下，真实模型生成并发布了保留企业、月份、F002、用途/备注、限制和待办的摘要，且查询返回正确发票；但工具结果加入后超预算，总体以 `CONTEXT_CAPACITY_EXCEEDED` 结束，保留了正确查询卡片并说明后续未完成。随后 44000/24 轮和 36000/12 轮的两组独立测试中，模型将 `covered_sources` 返回为多个嵌套列表，系统以 `SUMMARY_INVALID` 终止，未发布无效摘要，原文保留。未继续调整预算或挑选成功结果掩盖失败。证据：`live-long-context-v2/`、`v3/`、`v4/`，各含 `long-agent.json` 和实际模型输出。

8. **异常恢复：三类真实进程/数据库故障恢复通过。** 脚本创建自己的子进程，分别在提交前、提交后终止；另注入提交成功后的回读连接中断。恢复时先 `get_invoice_operation` 核对原操作，每项只一条操作记录、发票只增加一次修订，旧 fencing token 被拒绝；恢复回复由真实模型生成。故障本身是受控注入，不是模型供应商自然故障。证据：`live-recovery-v3/report.json`、三组边界、回执和 trace。模型超时及连续错误在此前程序故障测试中覆盖，本轮未制造真实供应商持续超时。

## 待修复项及优先级

- **P1：自动压缩遇到实际模型的分组来源列表后整轮中断。** 两组独立长对话均复现。模型输出 `covered_sources=[["s1",…,"s5"],["s6"],…]`。`backend/app/compaction.py` 的 `_decode` 仅兼容单层单包装列表，多组嵌套在进入既有来源覆盖修复前被拒绝。拒绝无效引用是正确边界，但当前版本对已观察到的格式不能恢复。修复应采用明确且有界的格式修复，再严格检查完整来源集合、正文不变及权限，不能接受缺失/额外来源或任意递归展开。
- **P2：工具停用后不能给出正常解释。** 查询能力撤下后无越权，但最终回复协议失败。应让页面得到“当前能力已停用”的真实状态，避免空最终消息；复验同一共享 Skill 的两个 Agent 及恢复启用。
- **P2：压缩后未为工具结果留足输入空间。** 28000 预算场景已有摘要和正确查询结果，仍在生成最终回复前超限。需保留该反例，检查下一步工具结果预算、历史取舍和降级策略；不以单纯增大默认窗口作为通过依据。
- **P2：月度业务回复未体现有效的回复风格偏好。** 固定模板渲染位于 `backend/app/answer_renderer.py` 的 `monthly_summary` 分支；本轮观察为详细、简洁、适中最终文本相同。若产品承诺这些偏好作用于业务答复，应在保持可核验金额和状态的前提下落实表现差异。
- **P2：窄屏运行洞察返回按钮不可点击。** 复现及 trace 见上一轮报告，本轮未修改此布局。

## 证据与限制
