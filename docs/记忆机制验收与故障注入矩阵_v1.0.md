# 记忆机制验收与故障注入矩阵

日期：2026 年 10 月 25 日。版本 v1.0。状态：测试设计，全部用例尚未执行。

依据[记忆与上下文融合机制](./记忆与上下文融合机制_v1.0.md)。本文件规定后续必须怎样证明可靠性，不包含已运行测试或准确率结果。

## 1 测试分组与通过原则

| 分组 | 检验什么 | 实际环境与判定方式 |
|---|---|---|
| A 程序一致性 | 持久性、事务、幂等、版本、隔离、恢复、输入覆盖 | 真实 PostgreSQL 独立测试库/临时 schema；模型可使用明确标记的测试 Adapter，断言数据库实际状态 |
| B 真实模型行为 | 语义理解、指代、更正、记忆写入判断、事实支持度 | 固定模型/参数/预算和对话案例，不把测试 Adapter 成功当真实模型通过 |
| C 恢复演练 | 真实进程退出、索引损坏、备份恢复、删除一致性 | 独立测试环境恢复到指定点，比较权威记录、版本、回执和业务结果 |

A/C 的硬错误一项即不通过，不能被 B 的平均分抵消。通过只适用于记录的代码、数据库、存储配置、模型/索引版本和故障范围；不扩大为任意故障、任意语义零遗漏承诺。

## 2 独立判定依据

测试驱动在系统之外保存输入序列、请求 ID、故障注入点和实际收到的回执，形成预期状态表。受测系统自己的日志不能作为唯一正确性证明。

每个案例至少记录：测试 ID、数据基线、用户/企业、执行顺序、代码与配置版本、提交回执、期望当前值与修订、数据库实测值、派生检索结果、实际模型输入清单、通过/失败及证据路径。

原始记录检查内容与归属；偏好检查稳定键、当前值、修订、删除代次与来源；任务检查企业/月、状态和操作关联；业务操作检查实际行内容及有效提交次数。只比数量或只断言某函数调用一次均不充分。

故障注入按事务前、提交后回包前、领取后、结果写入前等明确位置控制，避免只用随机等待碰运气。主进程测试和后台任务交错测试都记录事件顺序。

## 3 硬性用例矩阵

所有下列状态初始为“未执行”。每个“必须结果”均为验收目标，不是已完成声明。

| 编号 | 场景与注入点 | 必须结果 | 对应保证 |
|---|---|---|---|
| NL-01 | 原文事务提交前退出进程 | 无成功受理回执；原请求重试后只有一份完整已受理记录 | G1 |
| NL-02 | 原文提交成功后、回包前退出 | 重试读取原身份；正文/来源/工作项存在，无重复消息 | G1 |
| NL-03 | 模拟数据库不可写 | 不返回已保存/已记住；不产生只在内存存在的成功状态 | G1/G2 |
| NL-04 | 原文与 outbox 提交后、worker 领取前退出 | 重启能发现工作；不能出现已受理却完全无记录的处理缺口 | G1/G2 |
| NL-05 | 后台完成结果落库后、回执前重启 | 再次领取/核对不会重复创建已接受修订或重复业务写入 | G2/G5 |
| NL-06 | worker 租约过期，由新 worker 接手后旧结果返回 | 旧执行代次无提交资格，不覆盖当前状态 | G2/G4 |
| NL-07 | 两个请求同时更正同一偏好旧版本 | 一个按预期版本提交，另一个发现冲突；无静默覆盖、无双当前值 | G2/G4 |
| NL-08 | 同用户跨企业读取或按 ID 更新/删除记忆 | 范围匹配；错误企业的 ID 不被读/改/删 | G6 |
| NL-09 | 切换用户后查询同企业任务和偏好 | 无其他用户的任务/偏好进入输入或结果 | G6 |
| NL-10 | 新建会话继续已有任务 | 精确恢复正确企业/月/代次，随后重查当前业务状态 | G2/G5 |
| NL-11 | 更正偏好后旧向量仍排名第一 | 权威读取排除旧版本，新值保持有效 | G4 |
| NL-12 | 删除偏好与旧后台提取交错，删除先提交 | 迟到结果不能创建有效旧值，索引未清完也不泄露到模型输入 | G4 |
| NL-13 | 删除后用户明确重新记住，再返回旧任务 | 新代次有效，旧任务不能替换或删除新代次 | G2/G4 |
| NL-14 | 摘要引用偏好后偏好被更正/删除 | 该摘要失效或重建；普通上下文不带回旧值 | G4 |
| NL-15 | 被压缩区间仍有未记账来源或处理失败缺口 | 不静默切换到只含摘要的新视图；缺口可见，原文仍可读取 | G1/G3 |
| NL-16 | 摘要模型失败、返回无效结构或运行中退出 | 旧视图与权威状态保留，没有先删原文再失败的窗口 | G1/G3 |
| NL-17 | 摘要生成期间任务被替换或偏好变更 | 陈旧候选不能发布；重建或明确停止 | G3/G4 |
| NL-18 | 构造超过预算的必需任务/偏好输入 | 不静默裁掉必需字段；停止或缩小范围，保留权威状态 | G3 |
| NL-19 | 压缩点落在工具调用与结果之间 | 保留完整配对与未知状态，不生成孤立调用或假成功 | G3/G5 |
| NL-20 | 文本/向量索引不可用 | 已知任务仍从权威库读；需要历史证据的动作明确降级/停止，不伪装无记忆 | G2/G4 |
| NL-21 | 清空派生索引后重建 | 仅从当前合法来源重建；已删/更正旧值不恢复有效性 | G1/G4 |
| NL-22 | 一张发票保存时让任务写入失败 | 同事务整体回滚，或依设计返回真实未提交结果；不出现发票改了而账本/任务丢失 | G5 |
| NL-23 | 发票事务提交后断网，再发同操作 ID | 查询已有操作结果，不再次产生有效修改 | G5 |
| NL-24 | 提交成功后核验读取失败 | 区分已提交与未核验，不谎报完全失败或已核验成功 | G5 |
| NL-25 | 续办前另一用户已补完一张发票 | 新检查反映当前缺项，旧任务清单不覆盖当前数据 | G5 |
| NL-26 | 两家企业存在同号发票，用户更改其中一家 | 只有目标企业允许字段改变，另一家完全不变 | G5 |
| NL-27 | 规则停用/更新后旧记忆和摘要仍存在 | 使用当前合法依据；无有效规则时说明不足，不根据记忆恢复旧门槛 | G3/G4 |
| NL-28 | 较早来源失败，后续来源正常处理 | 可处理后续独立项，但连续水位不跨缺口；修复后可完成而不重复已完成项 | G1/G2 |
| NL-29 | 应用退出与重启，核对受理和保存成功回执集合 | 所有落在可恢复持久提交范围内的确认记录正文、值、版本一致 | G1/G2/G5 |
| NL-30 | 从一致备份恢复到指定恢复点 | 恢复点内原文、当前指针、修订、操作账本及删除状态一致，可重建派生资料 | G1/G2/G4 |
| NL-31 | 仅有较旧备份但用户删除/更正在其后 | 不声称恢复到最新；未补齐后续记录前不开放陈旧有效记忆 | G4 |
| NL-32 | 输入所用关键来源在发送前校验时已失效 | 不发送陈旧输入或提交依赖动作；重建/停止可见 | G3/G4 |
| NL-33 | 旧来源在新更正提交后才被领取，提取时已读到最新目标版本 | 仍按来源顺序拒绝旧指令修改当前值，不能靠重读绕过更正/删除 | G2/G4 |
| NL-34 | 模型请求发出后用户更正/删除，旧请求之后返回 | 不能撤回已发送输入，但迟到正式答复/写操作不得提交；新请求使用新状态 | G4 |

NL-01、02、05、06、07、12、17、22、23 至少覆盖不同交错顺序。次数和随机种子写入报告，重复通过不能代替对未覆盖提交窗口的测试。所有持久性案例使用真实数据库提交与重启，不能以 SQLite/内存行为替代 PostgreSQL 语义。

## 4 必需输入覆盖检查

每次长对话、压缩与恢复案例均对照独立预期状态，检查模型实际输入中企业、月份、任务代次、待补信息、当前关键偏好、必要规则条件和真实操作状态。旧值或其他用户企业信息应不存在。

输入清单与真正发出的请求绑定；不能只检查清单里声称 selected 而实际内容未进入请求。密钥与凭据不进入记录。

检查通过只能证明提供了正确必要信息；模型是否遵守由真实模型与业务结果检查判定。

## 5 真实模型对话案例

| 编号 | 场景 | 检查重点 |
|---|---|---|
| LM-01 | 用户清楚指定企业/月与检查任务，中间加入无关话题 | 回到任务时少重复询问，目标仍正确 |
| LM-02 | 用户在同一句中补用途、修改展示偏好并提出问题 | 业务、长期偏好与临时问题正确区分；无明确持久意图不乱存 |
| LM-03 | 更正包含否定和时间条件，例如“上次说的取消，这次只看甲企业” | 不把临时限制升级成永久偏好，不忽略否定 |
| LM-04 | 要求记住、随后更正、删除、再新会话查询 | 使用当前值或如实无有效记忆；删除后旧值不复活 |
| LM-05 | 模型建议过一个用途，用户没同意 | 不认为建议已经是用户事实或修改授权 |
| LM-06 | 用户说“继续上次的”，但有企业歧义或无任务 | 只追问缺少信息，不猜月份、企业或已完成状态 |
| LM-07 | 长上下文触发压缩后指代前一项补充 | 目标明确才写；必要时定位原文或澄清 |
| LM-08 | 用户问旧偏好或原话 | 明确区分历史与当前；用户删除后不以普通历史问题恢复已删有效偏好 |
| LM-09 | 用户要求按记忆中的旧规则执行 | 解释当前适用规则，不以偏好或历史覆盖规则 |
| LM-10 | 工具报错、部分成功、结果未知 | 回答与真实状态一致，不捏造成功、零金额或全部完成 |

准备与开发样本独立的表达变体和对话顺序，覆盖中文指代、省略、更正、跨会话和多用户企业组合。按 PRD 建议基线统计完整任务完成率，同时报告重复追问、旧值误用和证据支持率；任何错误业务操作仍单独视为硬失败。

## 6 对照实验与测试报告

可对照近期窗口、近期窗口＋摘要、现有来源/文本召回基线、融合机制。统一模型、数据、输出预算与工具，记录输入 token、模型调用次数、延迟和费用；语义召回与业务正确性分别统计。

测试报告必须写明未覆盖范围和实际配置。当前仅完成设计，所有 NL/LM 用例均未运行，数据丢失率、召回率和压缩收益均无实测值。
