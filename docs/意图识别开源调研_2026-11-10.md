# 开源项目的意图理解和工具选择调研

调研时间为 2026 年 11 月 10 日。以下按项目公开源码与官方文档梳理。所述机制反映来源页面的实现，不代表本项目已实现或任何项目能保证模型选择正确。

## DeepSeek Harness

Agent 循环将系统说明、会话历史和工具声明组合进请求，模型产生普通回答或工具调用，运行时派发工具并将结果写入日志，再进入后续模型步骤。当前可供模型使用的工具定义由工具注册表提供。历史检索工具属于可选的实验能力，工具提供名称、参数及描述，由模型在合适的时候调用；工具执行时还需检查调用者所在工作区的授权范围。循环没有证明存在每次工具调用之前的独立自然语言意图分类器，也不能据此保证不会误调工具。[核心循环](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.md) · [历史工具注册和模型提示](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/tool-session-query/src/index.ts) · [历史搜索实验入口](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/session-search/README.md)

**适配判断**：可以借鉴完整记录、模型与工具迭代、工具前权限检查、工具结果与调用配对、失败可追踪。使用单一 Agent 并保留财税宿主的范围和写入校验；不能因为迁移循环就推断模型能正确处理“今天星期几”。对 `search_conversations` 提供清楚的适用边界仍需真实模型测量。

## LlamaIndex 路由查询

`RouterQueryEngine` 将候选查询引擎包装成带元数据的工具，调用 selector，根据查询与元数据返回一个或多个候选和选择原因，再调用对应查询引擎。多引擎结果可做组合，选择结果可附在响应元数据。查询工具有 name/description，默认说明相当宽泛，因此实际项目需要写清各知识源范围与使用时机。[路由源码](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/query_engine/router_query_engine.py) · [工具元数据源码](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/tools/query_engine.py)

**适配判断**：可借鉴明确描述候选、在轨迹中保留路由理由，以及多来源组合结果。但其 selector 自身仍可能选错，候选集合与用户问题不匹配时不能当成自动安全的通用入口。正式规则、用户上传资料、历史聊天需有各自权限与来源校验，不能靠描述替代。普通问题需要直接回答或澄清路径，不能把全部消息强制送到知识路由器。

## LangGraph / LangChain 路由和对话

官方文档将 router 描述为可用模型或规则实现的路由步骤，区分直接分发与由 supervisor 在持续交互中选择。对多轮情况，文档示例用会话 Agent 包装无状态路由器，由会话 Agent 持有对话上下文。图工作流提供条件边，从模型节点根据其结果进入工具节点或结束。该设计支持插入检查点，但路由节点、模型、条件边本身不自动确保分类准确或证据有效。[官方路由指南源码](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/multi-agent/router.mdx) · [工作流与条件边源码](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/workflows-agents.mdx)

**适配判断**：可借鉴把路由结果、工具节点和验证节点分别记录，并让当前会话上下文参与追问。不因此引入多 Agent 或固定每条消息都增加一次模型调用，应通过同一测试集量化路由收益、时延和失败；模型不能跳过后端授权。

## 针对项目的问题与下一步实验

用户新会话询问「今天星期几，具体日期」时，原始轨迹显示模型先调用 `search_conversations(query="第一张")`，搜索无结果后选择 `acknowledged`，程序渲染固定文本「本轮未修改发票数据」并标记完成。当前工具描述允许查询本人历史但主要强调功能和范围；系统提示既有业务规则也有发票序号示例。**目前没有证据将误搜唯一归因于工具 description、某个提示句或模型。** 已确认的程序侧事实是 `acknowledged` 固定渲染不能回答日期问题，最终交付缺乏对这一需求的有效覆盖。

建议先冻结多场景测试，覆盖日期/状态/普通闲聊、无关联历史、明确历史请求、正式规则、知识资料及其代指、切换话题、多问题与权限负例。给每例写预期目标和允许工具集合，保持模型、输入快照、参数和环境一致，记录模型第一次动作、全部工具调用、最终答复、证据、耗时与 token；按模型随机性重复，并保留原始失败。

对照实验分开验证：基线；仅明确工具 description（使用场景、非适用场景、参数来源）；仅精简或修正系统提示；组合改进。日期无须历史工具，可用可核验的宿主日期与时区直接交付。规则、金额和写入证据依然应按当前身份、企业、版本和状态校验。再视结果比较是否需要独立路由步骤及其额外延迟与误判，不以规则关键词固定处理所有请求。样例和盲测应包括“先查知识、再问续借”“查 A/B 后问这个”“转问日期”及混合多意图，防止短句假通过。实验完成前所有根因和改进幅度均为待验证。
