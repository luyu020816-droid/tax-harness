# 财税连续办理助手：实现说明

系统围绕赛题的月度查询、用途补充和连续办理设计。用户通过对话表达目标，在工作台核对结果与任务；记忆管理允许查看、更正、取消和删除，运行记录展示实际输入与执行证据。

Python 后端集中执行业务约束和数据一致性，TypeScript 前端负责交互。模型通过同一个工具循环理解、选择工具、追问与解释，不直接执行 SQL、不拥有身份切换能力、不计算财务真值。发票按企业和票号唯一定位，金额用 NUMERIC，运行角色只能更新用途与备注。

## 记忆如何存储与寻找

来源层保存用户原话、受控界面操作、真实工具结果与正式答复，带归属、修订、哈希和来源顺序。来源不由摘要替代，也不因上下文裁剪而消失。

正式层保存任务 slot、修订、显式长期偏好、待澄清事项与操作账本。任务按用户与企业索引，换会话仍可恢复；企业未知时保存待澄清，不先猜企业。revision、generation、authority_source_seq 和 memory_epoch 分别防止并发覆盖、删除后旧对象重生、旧来源覆盖新决定和在途输入过期。

派生层是历史文本索引和摘要。每次先精确读取当前任务与有效偏好，再取近期合法历史，必要时通过工具查完整原文。首版使用文本和实体条件，不把向量库存在等同于可靠记忆。摘要只帮助定位，当前金额、规则和操作状态仍须查真值。压缩检查来源处理是否完整、工具调用是否闭合；错误候选不覆盖旧视图，原文继续保留。

更正删除会使派生摘要失效，相关旧来源退出普通召回。其他仍有效的正式事实可以引用自己的不可变证据，避免误删同一消息中的独立事实。受控核对审计仍存在，界面不宣称已经全面擦除原文。

## 保存与连续办理

写入先定位当前 revision，核对本轮原话、企业、票号或有效展示列表。同一来源对同票只有一个冻结意图，换工具调用编号不能再次保存；双字段合成一个 patch。事务同时提交业务、操作账本与任务变更，回读区分已核验、待核验和后来已变化。

用途保存后重新检查当前任务，持久化真实剩余项及数据/规则版本；只有零缺项且 head 未变化才完成任务。“继续”只恢复目标并重查，不重新授权旧修改。

模型请求前记录实际 payload、任务偏好依赖、来源、规则版本和预算，正式答复提交前再次校验。租约与 fencing token 阻止已被取消、接管或切换范围的旧执行提交。失败时保留已确认操作，未知状态不能解释成成功。

一致备份包含正式状态、来源、修订、删除代次、账本与水位，并与独立回执核对。旧备份缺少后续更正删除时保持维护状态。单机介质全部损坏后的最新数据零丢失，需要额外同步副本，不属于本版已验证保证。

## 界面与验证

深色窄导航、浅色主区、单一绿色主操作；默认仅展开对话。金额、缺项和保存以结构化卡片表达，规则和运行输入放入详情抽屉。小屏收起导航，表格局部滚动，输入法组合状态不发消息。

已通过真实 PostgreSQL 的 62 项测试与真实 Chrome 主流程。模型接口由用户稍后配置，尚无模型成功率。冻结集包含十类四十例，每例计划三次，确定性断言和人工语言复核分开。完整故障矩阵、策略对照、正式录像和干净机器验收仍是提交前工作。
