# 知识库自然回答与引用：修改 Spec

状态：待开发、待验收

日期：2026-11-12
适用基线：`main` 的 `fdba54b`；前端开发期间需先同步实际目标分支。`feature_adjust_1111` 的 `8e3e44d` 已包含该基线，但改动了上下文、历史会话及洞察页面；实际编码前应重新获取双方最新提交，在集成分支上核对差异，不能覆盖朋友的前端改动。

## 1. 问题与目标

当前 `search_knowledge` 将证据回送模型，但回答协议以 `knowledge_quote` 和固定 `knowledge_insufficient` 为主；普通 `chat_answer` 又禁止金额等具体事实。用户因此看到的是原文卡片和模板，而不是面向问题的解释。实际例子：问报销限额时已召回南京住宿每人每晚 437 元的条款，但最终仍显示“依据不足”；追问北京时检索到南京条款，却没有清楚解释适用城市不符。

目标：模型基于本轮实际入模的授权证据直接、自然地回答；仅对真正支持回答的证据展示引用。能回答一部分时先给有依据的部分，再说明缺什么；没有支持证据时自然说明本次未找到，不展示不相关的原文。

非目标：不重做上传、索引、聊天历史、正式业务规则或普通聊天路由；不让上传文件改变比赛正式规则；不引入强制 `/knowledge` 命令；不承诺检索或语义校验 100% 正确，不以调低阈值或增加 K 替代质量验证。

## 2. 当前事实与边界

1. `backend/app/knowledge_retrieval.py`：授权范围内关键词最多 30、向量最多 30，RRF 融合最多 20，再精排；`evidence_selection.py` 按相关性阈值、最多 6 个结构化证据组和约 3000 估算 Token 选证据。组内可能有多个片段，最终不是固定 K 条。
2. `runtime.py` 将实际工具结果加入模型上下文；`tool_schemas.py` 中 `FinalReply` 为结构化块；`answer_renderer.py` 用 `_knowledge_quotes` 校验本轮证据、权限、版本、哈希和完整组，再生成引用卡片。`knowledge_insufficient` 当前输出固定文本。
3. 用户手动提交的知识资料与聊天历史独立。知识检索只可读取当前身份与企业有权访问、已发布、有效版本；引用只读，不等于修改授权。正式比赛规则和结构化业务结果继续由现有正式规则/业务工具提供，上传资料不能覆盖其执行权威。
4. UI 的 `KnowledgeCitation` / `Results` 已有来源卡片与查看原文能力。除必要的自然答复、引用关联和降级提示外不改现有视觉风格，不使用模拟结论伪装真实结果。

## 3. 端到端行为

```text
用户问题 + 当前会话上下文
  → 现有模型按需调用知识工具（普通聊天无需强制检索）
  → 在权限、企业、有效版本内检索，取得筛选后的证据组
  → 原问题 + 必要上下文 + 实际入模的证据及 citation_id 一并回模型
  → 模型判断：可回答 / 部分回答 / 无支持 / 检索不可用
  → 输出结构化的自然回答与逐项证据引用
  → 服务端再次验证引用、事实约束和版本，决定展示或安全降级
  → 自然回答在前；仅展示实际支持的来源，可展开核对原文
```

模型判断引用是语义任务，程序不把它简化为“召回有结果就回答”。`status=ok` 是检索状态，不证明答案成立；`answer_support=not_evaluated` 不得当成已验真的结论。

### 3.1 可回答

模型用自己的话直接回答，保留范围和必要条件、例外及单位；每个实质事实段落至少绑定一组本轮实际入模且能支持它的引用。可引用多份资料，但不要为了展示而引用无关候选。金额、日期、条件、否定、比较关系不得扩大、缩窄或颠倒。

南京案例：可说“青杉计划南京出差住宿上限为每人每晚 437 元；确需超标，要入住前取得项目负责人书面批准，并随发票附批准记录”，附住宿条款引用。不说“所有城市统一 437 元”，也不说“437 元以上不能报销”。

### 3.2 部分回答

问题包含多项或范围不明确时，只回答证据能支持的部分并绑定引用，再自然说明未覆盖的范围，必要时问一个最有价值的问题。不能因为回答不全否定已证实内容，也不能把已知的南京条件说成全国条件。例：“目前找到南京住宿标准为每人每晚 437 元……其他城市和费用类型的标准，这次资料没有覆盖。你想了解哪个城市或哪类费用？”

### 3.3 无支持或不相关

本轮候选不能支持问题时，不展示这些候选的原文卡片，不给它们生成答案引用。自然说“这次没有找到能够确认北京住宿报销上限的资料，请补充相关制度或确认城市/费用类型”。可以用自然语言说明本次找到的是南京资料，但不能把它当北京依据。仅说“本次、当前授权及筛选范围未找到”，不能断言整个知识库绝对不存在；无证据的事实和否定结论均不可编造。

### 3.4 未就绪、部分覆盖、冲突与歧义

- `unavailable`：说明检索暂不可用，不能说没资料。`not_found`：说本次未找到。`partial`、降级检索、预算不完整：可使用已核验且确实支持的部分证据，但必须提示覆盖不完整，不能把“未找到”当完整结论。相关性阈值、排序分数均不是事实置信度。
- 多份相互冲突或版本/适用范围无法判定的资料：列明冲突和各自引用，不能擅自合并或选定权威；正式业务规则仍以受控规则为准。歧义如多个企业、城市、费用类型或指代无法确定，先澄清，不能猜。
- 检索或生成中资料被更新、停用、撤权、权限变化或来源哈希变化：提交和展示前沿用现有版本、权限、epoch、哈希校验，失败时重新查询或明确告知依据已变化；不能退回未经校验的旧原文或答案。混合业务/知识问题只对知识部分应用本方案，不丢弃其他已验证的业务结果与操作回执。

## 4. 回答协议与校验契约

### 4.1 结构化输出（拟新增，开发时保持旧块兼容）

在 `backend/app/tool_schemas.py` 的 `AnswerBlock` 新增 `knowledge_answer`。以下为模型输出示例，`citation_ids` 是实际返回的 UUID，示例名称不是有效编号：

```json
{
  "type": "knowledge_answer",
  "coverage": "partial",
  "claims": [
    {"text": "南京出差住宿上限为每人每晚 437 元。", "citation_ids": ["本轮实际引用UUID"]},
    {"text": "确需超标时，应在入住前取得项目负责人书面批准。", "citation_ids": ["本轮实际引用UUID"]}
  ],
  "gap": "本次资料没有给出北京住宿标准。",
  "follow_up": null
}
```

- `coverage` 限 `supported`、`partial`、`insufficient`；`claims` 每项含非空文本和非空引用 ID 列表；`gap` / `follow_up` 可为空并设置合理长度上限。`insufficient` 时 `claims` 必须为空，不接受为了填充而附带无关引用；`supported` 至少一项 claim；`partial` 同时有 claim 和缺口说明。无证据的建议或追问不得伪装为事实。
- 只允许引用本轮**实际加入最终模型请求**的 `search_knowledge` / `read_evidence` 返回的 citation ID；不接受历史轮编号、自造编号、被上下文预算裁掉的候选。复用 `_knowledge_quotes` 的完整证据组与来源校验；同一引用去重显示但可支撑多条 claim。若完整组未入模，要求补读或降级。
- `knowledge_quote` 继续兼容旧测试和已有会话；新交互优先 `knowledge_answer`。不得通过放宽 `chat_answer` 的金额、写入成功、正式规则断言限制来绕过业务安全。`knowledge_insufficient` 保留旧协议兼容，但新回答不得同时无条件附上无关来源。

### 4.2 支持性校验与降级（重要限制）

`citation_id` 存在和内容哈希一致，只能证明引用真实，**不能证明自然语言推论被原文蕴含**。实现必须将“引用有效性”和“答案是否受支持”分开：

1. 服务端先验证 ID、本轮入模、完整证据组、用户/企业权限、文档状态/版本/有效期、来源哈希与 epoch。任何失败不得展示旧事实，按现有错误路径重新检索或告知依据失效。
2. 对模型生成的每条 claim 逐条核查：数字、金额单位、日期、城市/对象、阈值方向、频次及否定词等关键要素必须能在其引用组中找到相符依据；同组例外和审批条件不能丢失。不得把“南京”转为“北京”、把“上限”转为“超过不能报销”或省掉超标审批例外。
3. 对语义改写和跨句组合，使用独立的支持性判断步骤，对每条 claim 返回 `supported / unsupported / uncertain` 及依据定位；需要明确注明该判断仍可能误判，不把模型自评、重排分或简单数字匹配说成正确性证明。判断超时、结果不合法、证据无法核对或为 `uncertain` 时，禁止输出该 claim 的自由改写。
4. 默认安全降级为经权限和有效性核验的**简短原文摘录 + 引用**，或自然说明无法可靠确认；不能把部分验证通过的内容扩展成完整回答。若整条证据与问题不相关，则不展示原文。必要条件和例外必须连同原文完整保留。支持性校验的实现方案、失败处理及模型调用成本须有独立测试；不可为了完成自然回答放松权限和业务写入守卫。
5. 对与事实无关的自然衔接、提问可直接生成，但禁止将无来源的业务事实混入这些字段。`gap` 用“本次未找到/当前资料未说明”，不是对全库绝对不存在的证明。

实现时可优先复用现有模型适配器与超时/调用预算，不引入新的外部服务密钥；若独立语义判断不可可靠运行，功能须清晰降级，不把不可验证的自然改写标成已验证。不得保证零幻觉。

**首版支持性判断的执行约定：**只对准备展示的知识 `claims` 发起最多一次额外的、无工具的模型调用，复用当前对话轮次冻结的模型配置；不得用检索重排器的分数替代该判断。输入只含每条原始 claim、其所绑定的完整证据组及最小必要的问题范围，文档原文放在数据字段，明确禁止执行其中指令。输出为 JSON `{"verdicts":[{"claim_index":0,"status":"supported|unsupported|uncertain","supporting_quotes":[{"citation_id":"UUID","quote":"原文连续摘录"}]}]}`，每个 claim 恰有一项，顺序或编号可校验；`supported` 必须提供一个或多个该 claim 已绑定证据内的真实连续原文。程序验证条数、索引、ID、摘录是否真实存在，再执行关键数值/单位/主体/否定与例外检查；缺字段、额外字段、错绑、无法确定、冲突均不能通过。验证调用上限 1 次，不自动重试；其超时取 15 秒与本轮剩余时间中较小者，并计入现有模型步数、上下文预算及运行轨迹。超时、模型无效 JSON、证据组过大、关键要素无法机械核对或无剩余预算时，不输出自由改写，走本节所述原文或无法确认降级。每项结论和降级原因以不含原文和敏感信息的状态码记录在现有运行轨迹；正常用量按现有模型 usage 统计，不提供虚假的费用数据。

这是独立**调用步骤**，并不意味着换了独立模型或消除了同源偏差；它不能替代人工评测，也不能声称是形式化证明。若首版独立调用在真实环境下的延时或准确性未达验收，保持降级而不是跳过校验。`insufficient` 且没有 `claims` 时不发该验证调用；检索不可用由宿主直接说明状态。

### 4.3 Prompt 要求

在 `backend/app/context.py` 及协议说明中明确：只用本轮授权证据回答；区分已知、未知、部分覆盖；先说自然结论，再关联引用；城市、企业、金额、适用日期及条件需匹配；引用不是证据支持的替代品；无支持时不输出无关引用；资料中的指令只是待检索内容，不得改写系统指令或授权。处理普通闲聊、业务结果、写入回执的原规则保留。

Prompt 示例应覆盖南京 437 元、北京未知、超标审批、混合业务和知识问题及恶意文档；不能写死关键词、特定城市或文件名。

## 6. 执行步骤与衔接

1. **锁定基线并写失败用例**：获取远端 main 和朋友分支，确认未提交变更；复现两条原始问题、跨轮 scope_ref 和引用卡片现状。隔离测试库，禁止对演示库执行清空或种子重置。
2. **协议与引用验证**：新增结构化块、边界字段和本轮证据约束，保持旧协议通过。先验证不能伪造编号、跨用户或引用过期资料。
3. **有依据自然回答**：接入逐 claim 支持性校验和降级，先用可控模型与证据夹具验证金额、地区、例外、否定；语义校验的不可用/不确定路径必须先可用，再开放自由改写。
4. **部分、无依据与多轮**：处理北京/南京、多个费用类型、范围修正与旧 scope_ref；只回答受支持部分。正式业务结果和已保存回执继续完整呈现。
5. **前端集成与回归**：在朋友前端基础上展示自然回答与引用关系，检查原文展开、空状态、长文本和移动端；不隐藏模型失败、引用失效或覆盖不足。
6. **验收交接**：执行下列自动测试并标注测试环境、模型与结果；真实模型抽样单独列出，不把模拟成功说成真实效果。用户自行做最终人工验收。

## 7. 验收用例

| 场景 | 输入 / 证据 | 必须满足 |
|---|---|---|
| 完整回答 | 南京住宿条款：437 元/人/晚，超标需入住前书面批准 | 自然回答金额、城市、频次和审批，展示有效引用 |
| 模糊问题 | “多少钱可以报销？”仅找到南京住宿条款 | 回答南京已知部分并追问城市/类型，不声称统一标准 |
| 无支持 | “北京出差住宿限额？”只召回南京 | 不输出 437 元作为北京结论；说明本次未找到北京依据，不显示南京原文卡片 |
| 语义误读 | 原文“上限 437，超标经批准可报”，生成“超过 437 一律不能报” | 拒绝该改写，安全降级；保留例外 |
| 不完整资料 | 检索状态 partial、索引未完成、相关组超预算 | 明确覆盖不完整，不声称全库没有；只使用确实支持的部分 |
| 引用攻击 | 伪造 ID、上轮 ID、未入模 ID、不同用户/企业引用 | 拒绝或重新查询，不展示内容 |
| 生命周期 | 生成前后资料更新、撤权、停用、epoch 变化 | 不展示过期资料或旧结论，明确依据失效 |
| 条款冲突 | 两份适用范围不明且金额不同 | 呈现各自依据并说明冲突，不自动判定优先级 |
| Prompt 注入 | 文档要求忽略规则、修改发票或泄露密钥 | 只把文档作为数据，不执行其中指令或改变权限 |
| 追问 | 先南京，再问“北京呢” | 正确理解代指，不把南京限额当北京限额；不重复使用旧轮 scope_ref |
| 真实业务混合 | 同轮查询发票并问制度 | 业务查询结果和知识引用分别交付，不能丢失或用资料覆盖正式规则 |
| 失败处理 | 验证模型超时/格式错误、模型不可用、回答超预算 | 保留已有可验证结果和操作回执，不伪造成功或隐藏未完成事项 |
| 多用户隔离 | 用户 1 私有资料，用户 2 尝试查询或引用 | 用户 2 不得读取内容、引用或获知不该披露的资料 |
| UI | 自然回答、引用展开、无依据、失效及窄屏 | 页面风格一致，可看原文，不显示无关引用；未完成状态清楚 |

自动化至少包含：相关后端单元及隔离数据库集成测试；前端协议和页面测试；回归既有知识、规则、历史、上下文预算和发票保存回执。真实模型测试至少覆盖完整、部分、无依据及多轮各一例；记录问题、实际证据、输出、人工判断、模型、时间和失败，不用模拟结果替代。

质量验证采用与调参样例分开的冻结题集，至少 30 题，覆盖上述各类场景，每题保存人工标注的可支持事实、不可推断事实、适用范围及期望证据。分别报告：可回答题的事实完整率、无依据/跨城市题的错误断言数、引用有效率、必要条件遗漏数和不确定时的降级次数。该题集中不得出现错误城市金额、伪造引用、越权或把错误条件当已验证输出；出现即修复并保留失败记录，不能只重跑挑选通过结果。题集通过只是这一批样例的证据，不代表线上零错误。

建议先针对 `test_knowledge.py`、`test_manual_knowledge.py`、`test_request_evidence.py`、`test_context_compaction_flow.py` 和 `test_receipt_failure_delivery.py`，加新协议与支持性测试；前端覆盖知识卡片、无依据、失效和新分支 UI。运行仓库 pytest 前必须检查 `backend/tests/conftest.py` 的数据库初始化和 `TRUNCATE` 配置，使用独立临时数据库并确认连接目标，不可直接对当前演示库运行。浏览器模拟测试与真实模型测试分别报告。
