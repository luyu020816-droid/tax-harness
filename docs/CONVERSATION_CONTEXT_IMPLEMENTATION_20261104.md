# 会话上下文与独立历史检索：实施记录

记录日期：2026-11-04。适用分支：`feature_adjust_1031`；会话改造已推送为91a43e3；后续专项验收另行记录。依据为[已评审设计](superpowers/specs/2026-11-03-conversation-context-design.md)和[DeepSeek Harness原始实现调研](DEEPSEEK_CONTEXT_RESEARCH_20261103.md)。

## 结果与边界

取消当前会话固定最近12轮的SQL/组装截断，改为原始记录、预算投影和有界摘要。聊天历史与知识库保持独立：普通聊天不自动进入知识库；用户主动寻找旧聊天时，使用独立日期/中文词法搜索，再按来源ID精确回读。已保存业务、任务和偏好继续独立管理，历史指令不能替代本轮写入授权。

这次完成A—C实现和部分D自动验证，不代表完整人工验收或比赛最终提交。用户偏好候选与确认机制仍为独立TODO。

## 具体实现

| 模块 | 变化与约束 |
|---|---|
| 原始日志 | 013迁移新增追加会话事件，source/run event在同事务映射；旧记录明确标记legacy_imported。普通运行角色不能修改原文、hash、角色或删除事件；当前任务和业务状态仍可更新。 |
| 投影 | `conversation_projection.py`按事件和权威source原文重建当前会话，不信任可变展示字段；失败/中断的用户输入仍保留。真实历史工具调用配对闭合，调用ID加历史命名空间。 |
| 预算和压缩 | `context.py`和`compaction.py`按预算组织输入，累计覆盖source和实际事件水位；摘要仅提供导航，原文不被摘要替代。摘要候选原子发布，来源变化、失败或必需内容超预算时明确失败，不能静默丢弃未覆盖历史。 |
| 独立搜索 | 014迁移新增可重建的中文词法索引。`conversation_history.py`支持时间、关键词、会话范围、稳定游标和原文续读，不混入knowledge表。默认每页5条、最多10条；回读每页1200字符，可继续读取。 |
| 工具与交付 | 新增`search_conversations`/`read_conversation`。模型可提交实际收到的citation_id，由程序解析原文；伪造来源拒绝。历史助手建议明确作为当时记录，不作为当前执行回执。 |
| 权限和失效 | 检查用户、当前企业授权、原会话状态和source hash；原知识依赖停用时重验，不能通过旧聊天恢复禁用知识。归档可搜索，逻辑删除停止聊天召回，保留独立业务与审计。 |
| 前端 | 保留原有UI风格，历史卡片显示角色/时间、原会话链接和原文续读；撤权或删除后清除已展开正文。新API位于`/api/v1/conversations`，旧混合入口继续关闭。 |

保留PostgreSQL，不增加另一套JSONL权威存储；不扩展通用编码Agent，不改真实模型密钥，不开放生产认证。旧`CONTEXT_RECENT_TURNS`仅为历史实验兼容字段，新投影不使用它截断。

## 审查与修复

实施前按规范与设计分别审查；发现项已落实修复并进入回归，包括：

- 关闭摘要必须先恢复原始组，避免同时排除摘要和被覆盖历史。
- 原文hash/依赖损坏不得静默跳过；原文以sources为准。
- 摘要覆盖水位只能来自实际覆盖的sources，不能吞掉运行中的新事件。
- 历史工具结果不得冒充本轮交付或保存回执；旧工具ID需要命名空间。
- 删除/撤权后前端展开内容也要清理，晚到响应不得恢复旧内容。
- 专用导入角色建立词法索引不应额外获得私人聊天读取权限。
- 在线取消旧摘要回读工具，避免重复大结果挤占预算；引用由程序解析，避免模型重复抄写或漏填来源字段。

完整回归中洞察分页用例曾因Python时间上界未覆盖刚写入数据库记录失败；修复测试夹具，以数据库实际最大created_at固定同一数据集边界，保留分页不重复断言，没有据此修改生产分页SQL。注入损坏原文的测试使用管理员显式关闭/恢复保护触发器；普通角色不可变约束另有反例检查。

## 迁移和恢复

迁移脚本`scripts/migrate_conversations.py`要求维护模式、无活动任务和其他主库连接；备份、校验目录、恢复到新隔离库并核对全部表后，才应用迁移和发布索引。失败保留维护状态，不重导比赛样例。

本次备份为`.local/backups/conversation-20261103/before-conversation-upgrade.dump`，555472字节；恢复库`tax_harness_restore_311bd86f30f3`，58张表一致，受保护原字段升级前后不变。不要在仍有写入时直接覆盖主库；回退需先维护并核对升级后新增数据，再恢复匹配旧代码/旧schema的备份。备份不等于升级后新数据零损失回退。
