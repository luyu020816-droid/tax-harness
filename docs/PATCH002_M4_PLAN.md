# 第一批：知识检索质量与完整证据

日期：2026-10-30。承接已批准的整改SPEC第10、16节与路线图第4步。用户已明确开始第一批，本文件记录实施细化，不改变既定范围。

## 固定条件

沿用8bbb141的BGE-M3、重排、jieba、pgvector和结构分块。模型profile、语料、问题、标注、代码指纹都进入报告；不修改原40例或既有业务断言。当前不开发历史向量、OCR或新业务写工具。

## 三个交付

1. **完整证据选择**：根据已保存blocks/chunks的明确标题层级、条款边界、表格和续文关系建立证据组。同组的否定/例外/表头/单位一起回源核验。按组去重、最多6组、总预算3000估算tokens；放不下整组返回partial及预算不足，不能静默留下主句。引用继续逐chunk持久化并核权，不改变原文/hash。
2. **可追溯的相关性选择**：只在开发集校准真实重排logit的选择阈值，不把它称作正确概率。策略绑定实际模型profile、开发集hash及算法版本；缺失/不匹配时明确未校准。向量或重排降级不冒用hybrid的校准结果。候选相关性通过也不代表语义充分支持，模型仍须核对原文，允许knowledge_insufficient。
3. **冻结评测**：单独开发集；留出包含知识48题与权限/版本/无答案22题。本阶段不填充尚未实现的历史30题。按文档家族隔离，开发集同义改写不进入留出集。使用公开可提交的合成制度与明确证据单元、0—3相关性、必须同时找到的证据集合。标注由本次实现者编写，不能冒称独立人工验收。

## 执行和验收

- 先固定语料/标注与指标算法，再测旧选择策略作为基线；开发集拟合策略后锁定文件hash，才读取留出指标。不得看到留出结果后重新选择阈值并仍称独立留出。
- 比较词法、向量、RRF、加重排与完整证据选择；不需要改写时不伪造“加改写收益”。精确实体约束另做开关对照。
- candidate Recall@20按全部已标注必要单元计算，不用任意一条命中代替；nDCG@10用(2^grade-1)/log2(rank+1)。另报完整证据集合覆盖、引用定位/hash、无答案误接收、越权/陈旧版本、延迟、证据token预算及文档家族配对不确定性。
- 评测使用隔离数据库。可以缓存实际推理得到的查询向量以避免CPU反复加载模型，但记录实际缓存内容hash和生成profile，禁止假向量冒充语义成绩。模型加载耗时与缓存后的检索耗时分别标注，不称生产延迟。
- candidate Recall@20开发目标≥95%；必要证据完整覆盖另报。权限泄露与陈旧版本误用必须为0。未达到目标或人工语义复核未做时如实记录，不通过删题宣告完成。
- 新程序反例覆盖完整组预算拒绝、相同文本不同来源、旧版本/跨用户组扩展拒绝、策略profile不匹配、无答案与依赖失败区别。完成针对性与原程序回归后再更新8105预览。

接口保持KnowledgeRetrieval.search/read；新增选择和指标逻辑集中在小型纯函数模块。HTTP与模型工具共用同一实现，不另建只供演示的RAG流程。
