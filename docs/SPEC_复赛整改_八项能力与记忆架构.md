## 交付基础

### INT-01 · 两种旧数据库可原地升级

**入口与根因。** `cli.initialize` 只看 `schema_migrations.version`，`db.Database.ready` 只认版本号。A 的 024/025 是工作簿表和任务写计划字段，B 的同号文件是知识策略和摘要范围。简单拼接目录或把第二份 SQL 改个文件名都无法升级已经登记过旧编号的库。

**实现约定。** 统一树保留 A 的 024/025 作为新装的顺序，在跑旧编号前识别旧库的实际结构和已登记版本。用一个新的、仓内唯一的合并迁移补全缺少的一侧。识别范围至少覆盖两张工作簿表及关联索引、`write_plans.task_id/task_generation/task_period` 和关联约束／索引、两张知识策略表、`summaries.agent_scope` 和关联索引。对 B 旧库不能假设 A 的 024/025 已执行。对只到 024 的旧库也按实际结构补齐。新迁移和结构校验同事务，初始化并发要串行；识别到同名异型、无法解释的数据时中止并报告对象名。为后续迁移记录可核对的唯一身份或校验值。可选 vector 组件延续现有 profile 规则。运行账号的权限授予要包含两边的表。

**通过。** 空库、A 旧库、B 旧库分别升级两次，原有发票修订、会话、Agent 及两边各自独有的数据可读可用。缺少必要列或约束时探活返回未就绪。三种库均从业务入口完成知识策略读取、带范围的摘要选择、工作簿查询和用途计划确认／取消。

**交付切换。** 在旧库副本演练并保留升级前备份。部署时先让旧 worker 结束或释放租约，再执行合并迁移，检查就绪后启动同一候选版本的 API 和 worker。迁移中途失败时回滚该事务，保留旧数据；结构已升级但业务验证失败时停止新请求，使用已验证的兼容应用或在隔离库从备份恢复后核对。禁止直接删除新表、重置迁移编号或覆盖线上已提交操作来回退。

**通过。** 九月改十月后，“显示税额与含税金额”和“待财务复核”仍在，九月计算的缺项数不再视为当前值。只清除展示列时复核待办仍在。后台重新检查、旧请求重放及两人同时编辑不能覆盖较新状态。

### AR-07 · 一个企业内两件事可以独立续办

这是能力决策。用甲企业“九月发票查询”和“十月规则说明”测试分别更正、取消、换会话、切企业再返回及重启。先复用 `task_slots` 作为当前焦点和现有清单。若清单已能持久化每个事项的身份、状态和关联计划，补足入口与定位即可。若只能提示替换第一件事，在现有任务下增加稳定的事项 ID、事项修订和状态；旧活动任务映射为默认事项。只有验收场景中两个事项必须各自拥有独立任务生命周期，且子事项无法表达时，才扩展活动任务集合，保留旧 API 的当前焦点语义。

## 长期记忆与读取边界

### MEM-01 · 授权保存和内容忠实性分别校验

在 `tools.py`、`memory_changes.begin_change` 和 `preferences.change_preference` 分别处理聊天提议与本人表单操作。聊天路径核验引用属于本轮用户、原句确实存在、原句支持持久保存及拟存的具体值。常见格式偏好用有限的规范化映射，复杂自由文本按用户明确指定的原句存储，若需改写且原文不足以确认则展示拟存值、范围并询问。“仅本次”“不要记住”按相应分句处理，只进入本轮上下文。确认同样绑定拟存值、范围与目标版本。

**通过。** “只这次三行，不要记住”不产生有效偏好或新增修订；“以后请简短”遇到模型提交“详细”不能成功写入。明示保存、本人表单创建、明确更正、删除后按用户新指令重建都有正例。重启和新会话读取最终有效状态，旧来源不能把已删值写回来。

### MEM-02 · 来源限制贯穿保存、展示和模型输入

让 `preferences.py`、`memory.load_core`、偏好 API、历史和摘要读取共用可见性判定，输入包括当前用户、企业、Agent 限制、偏好作用域和来源当前权限。用户明确“仅甲企业”时服务端锁定 C001，模型传 `@user` 应拒绝或澄清。个人级格式偏好允许跨本人企业，前提是原话明确授权且该值可脱离企业事实独立使用。对遗留的“全局标签＋企业限定内容”先从有效读取中隔离，待本人校正。单条无权来源退出列表、召回与输入，其他合法事项继续；完整性无法确认时仅报告受影响的对象。审计历史按权限脱敏。

**通过。** 使用 U001/C001、U001/C002、U002 三组实际输入和列表比对。撤销甲读权后，乙的普通办理成功；乙和 U002 均无甲的标记，旧摘要和历史引用也不能恢复它。真正的全局格式偏好在 U001 两个企业仍生效。

### AR-02 · 更正按偏好身份和适用场景定位

写入前按“用户、作用域、适用对象或场景、维度”解析稳定身份；已有 `preference_id` 和修订继续用作更新目标。将常见 `response_length/answer_length` 映射到同一详略维度，正文与附录可作为不同场景。先解析原话，再核对模型提议。唯一匹配且明确要求更正时更新原 ID，多候选时让用户选择。新建和更正均在同事务中执行唯一性／修订检查。迁移可明确识别的别名；旧库已有相反值且无法证明先后意图时标为待消歧，保留修订与来源，避免同时入模。

**通过。** 两个会话先“简短”后“改成详细”，模拟模型给出两个合法英文键，最终只有“详细”生效且历史可查。正文简短、附录详细以及不同企业的偏好互不覆盖。冲突期间页面可以解决歧义，对话不能自行选一条保存。

### AR-05 · 让空历史的新会话也有可用预算

在 `memory.load_core`、`request_evidence.py`、`context.assemble`、`context_preview.py` 和实际发送前校验之间共用“授权后再选材”的规则。先取轻量身份与适用场景，按本轮请求选择正文。必要部分包括当前原话、当前授权和本轮动作适用的限制、待确认状态；一般模板按明确业务类型或选择的对象加载。未知适用范围的旧记录不可静默丢弃可能禁止当前动作的限制；可先读原文、澄清或阻止该动作。预估、实际输入及校验清单均基于本次选材，记录选择／排除原因和预算。固定工具定义按实际可用性裁剪并保留必要查证工具。

**通过。** 同一 16,000 输入预算、空历史、20 条年度附表偏好下，“一周有几天”可以正常回答，模型输入不含这 20 份模板。明确办理第 3 类附表时命中对应要求。适用于全部报告的有效限制仍然生效。记录本地估算和服务商实际用量，前次 14,920、28,061 仅作复现基线。

### AR-03 · 分别记录发送内容与结果的事实依赖

`context_snapshots` 继续完整记录当时的输入。另对可验证的派生结果记录决定其有效性的具体对象及修订，例如被展示的偏好、知识引用、任务状态或操作号。写入时由宿主根据工具结果、引用、确定性渲染与本次选材建立关系。自由文本如果真收到相关敏感值且无法证明无关，保守遮盖或重新生成该片段。修改 `memory_changes.suppress_old_history`、`conversation_projection`、摘要及审计的展示判定，允许独立保留仍获授权的原话或其他事实。保留对撤权、来源被删的重新校验。旧清单无法区分依赖时采用保守策略，不能将其视为没有依赖。

**通过。** 月报从项目符号改为表格后，“一周有七天”仍可续问；旧月报格式退出当前有效回答。删除一句话中的偏好 A 时，同句独立有效的 B 仍能使用。历史审计能说明当时为何这样回答，普通召回不会把已删值当现行要求。

### AR-04 · 按依赖范围处理并发和失效

`memory_changes.finish_change`、`tasks.apply_result`、`execution.guard`、`context.validate`、摘要查找与发布须使用一致的变更粒度。保留账号权限撤销的全局检查，对个人全局偏好、企业内记忆和任务修订分别记录版本。装配时记录所读范围及版本，包含可使本轮新增适用限制的范围版本；只校验已有对象会漏掉新规则。普通更正仅使相交范围重装，至多一次，连续变化返回可解释的冲突。业务写入仍在提交事务核验权限、目标版本、计划及幂等。旧执行缺少细粒度清单沿用保守校验，待新请求生成新格式。

**通过。** 乙的普通请求领取后，甲写入本企业偏好，乙原轮完成。若本企业新增适用限制，旧输入须重装或中止且零错误写入。全局撤权、旧租约丢失继续禁止提交。摘要晚到时若其依赖已失效不能发布，其他企业有效摘要仍可使用。

### AR-06 · 跨会话历史采用一个可解释的产品规则

默认只自动恢复当前任务和明确保存的偏好。用户明确回顾本人其他会话时，在当前授权范围内开放独立历史工具，附会话、日期、角色及来源。当前会话正常续问继续使用本会话上下文。由宿主在组装时决定本轮历史检索模式；系统指令、schema、`tools.py` 实际派发、分页／回读、`answer_renderer._explanation` 和预览共用这个决定。权限禁止或索引依赖不全时分别告知原因。历史助手答复只证明当时如何答复。

**通过。** 普通问候无跨会话搜索；明确要求“找我昨天在其他会话说的话”时有权 Agent 返回本人可见引用；禁用历史的 Agent 得到可渲染的边界说明。沿用已有词法／语义降级语义。已授权的当前会话摘要回读仍工作；失效游标不能读出旧范围。

### FILE-01 · 工作簿执行口径由本轮证据约束

**通过。** 表中 2026-10-01 交通费 12.30、10-02 住宿费 45.12、11-02 交通费 123.40。问十月总额为 57.42、两行；只看交通费为 12.30；按类别拆为 12.30 和 45.12。把月份、类别、分组任意一项传错均拦截。问“再看十一月”只更换授权变化的字段。核对原行号与金额列。

### FILE-02 · 金额单位也要有证据

在 `xlsx_workbooks.parse_workbook/calculate` 将币种列、原坐标、金额列标题与单元格格式中的可识别单位纳入快照。继承原 SPEC 的人民币元口径，支持原本合法且没有显式币种的普通人民币模板。出现明确币种列时，参与行须能确定人民币元；未知、缺值、外币、币种或单位互相冲突时返回具体表／单元格，整次计算无成功合计。使用现有精确十进制规则，保留负数、零和坐标。升级快照格式，旧快照缺少币种证据时从获授权原始文件重解析；原件不可用则要求重新提供，旧结果须重验后才能作为当前依据。

**通过。** 120 CNY＋10 USD 指出外币行，无人民币合计；改成两个 CNY 后为 130.00。覆盖外币仅在单元格格式里、单位为万元、显式币种为空、正常无币种旧模板和旧快照重启读取。只核算参与行；无法判断该行是否参与时提示定位。

### KB-02 · 用同一日期语义绑定查询

宿主从本轮固定日期表达解析日期，再与模型的 `as_of` 比较。支持 ISO、中文年月日和斜线形式，校验日历合法性。单个等价日期无须追问。多个不同时点且用途不明确、工具日期与原文冲突或月份与单日互斥时沿用澄清／范围错误。记录原片段、解析结果和选用的业务时区。与工作簿可复用小型日期解析函数，但制度有效日和工作簿行过滤分别建模。

**通过。** “2026-09-20”“2026年9月20日”“2026/09/20”对同一资料返回同版同条款。无效日期、错参和确有歧义的两日问法均有对照。省略日期时沿用现有业务默认并在结果注明。

### KB-01 · 发布和生效分开，引用按原查询时点核对

`knowledge.publish_in`、自动发布作业、检索候选、引用回读、工作簿当前版本检查共用选版语义。持久化“成功发布过”的事实；只完成解析的 ready 候选不可参加检索。接受 V2 发布后 V1 保留发布历史。给定文档、当前权限、指定时点，先排除停用／撤回文档与版本，再在有效区间内挑选已发布版本。有效区间采用左闭右开；同日有多个合规候选时采用最新成功发布的明确修订，记录依据。默认当前日期按业务时区。期间查询依现有完整期间覆盖规则，若期内换版需要区分依据则展示区间或询问，不能用期末版本冒充全月。工作簿文件版本时点与其行日期筛选分开。

引用及结果保存查询时点、版本及定位。取当前答案时重新检查现行授权、停用和该时点正确版本。历史引用回读须明确“当时适用”；停用、撤权后不返回正文。旧库从可证明的发布记录回填，无法证明曾发布的 ready 版本继续仅作候选。保留现行规则引用的换版约束及并发修订检查。

**通过。** 11 月 19 日发布 12 月 1 日生效的 V2，11 月 19 日仍为 V1，12 月 1 日为 V2，授权用户回查 9 月 20 日命中 V1。覆盖定时边界无服务重启、禁用和撤权立即生效、未发布候选、Excel 与文本共用语义。文件重复上传与他人更新仍遵守既有权限及版本契约。

## Agent 与能力管理

### AG-01 · 默认模型在受理时绑定，在重领时复用

在默认连接启用和本轮受理事务之间建立可判定的版本顺序。复用 `model_connection`、`agent_models`、`agent_authority.bind_turn` 和当前配置锁，为成功激活的默认连接赋不可变版本，并保存足以重建相同运行语义的非敏感配置标识。受理时将有效版本写入绑定；领取、重领、恢复及日志一律从绑定解析。凭据依现有安全配置加载，运行快照不存明文。进程重启找不到原版本时明确标记“原连接不可用”，告知可重新授权或新发。对历史未绑定版本的排队请求，仅在有证据确定旧版本时补齐，否则给出显式状态。当前管理停用或撤权规则仍须执行。

**通过。** 默认 A 时入队甲、启用 B 后入队乙，再领取甲乙，旧请求及其重领只用 A，乙用 B。增加测试失败的 B 未激活，以及另一 worker／重启无法解析 A 的路径。管理页、运行详情显示模型／版本，凭据不进入记录。

### CAP-01 · Skill 只在有效依赖齐全时装配

发布仍按 `agent_configuration.validate_skill_dependencies` 检查。运行时用 `agent_authority` 求出的实际工具动作、启停与知识范围，逐项核对所绑定 Skill 版本声明的必需依赖。缺任何必需依赖即不加载整段可执行指引，并给管理端列明受影响的 Agent、Skill、工具或动作。未受影响的 Tool 和 Skill 可继续提供。运行前再校验停用事件，已经受理的请求延续现有撤权语义，新请求不能继承额外权限；恢复启用只作用于满足原授权的新执行。

**通过。** 两个预置 Agent 共用“发票与规则核对”。停用 `find_invoices` 后两者的 schema 与系统指引一致退出相应能力，直接派发被拒，其他已授权能力可用。恢复后新请求重新生效。保留 Skill 版本固定和不同 Agent 的动作权限差异，两个界面预览与实际请求含义一致。

## 上下文与异常恢复

### CTX-02 · 必须保留的限制有可验证的原文位置

`summary_evidence.collect/validate`、`compaction.py` 先收集当前任务对象、显式禁止／更正、未办事项及定位，再分配摘录预算。一条过长的普通句不能阻断扫描后文。锚点记录来源、版本、可定位片段与摘要覆盖范围，原文可回读。发布前由宿主验证必需项的有效来源和覆盖情况。超预算时选择更短的准确摘录或保留未覆盖组供回读，无法保护重要约束时不把对应内容标为已覆盖。后续更正与失效须重验，旧摘要缺必要信息时重新生成或回退原文。

**通过。** 1,024 锚点预算、800 中文字符长前缀后出现“不得外发。票号F002尚待核对。”两条都可从下一轮输入或受保护的有效引用准确恢复，执行动作前必须能核实限制。返回空锚点却宣称已完整覆盖的候选不能发布。补测后续更正 F002、原来源失效及普通无关键限制的对照。

### CTX-01 · 预算先规划，再决定是否压缩最近五轮

`context.assemble` 与 `runtime` 的自动、手动压缩入口共用一次预算判定。先计当前输入、适用强约束、必要工具和待确认状态，再按近期优先选择完整历史组。最近五组是正常预算下的保留偏好；超预算时可从其中最旧的一组开始压缩。工具调用及对应结果作为完整组。预算不足要把可压缩候选交给现有压缩机制再装配，压缩请求本身遵守预算、租约与重试上限。最新用户请求、未消费的写入回执和必要业务状态优先完整保存。

**通过。** 16,000 输入预算、五轮各 2,200 中文字符后，第六轮仍可办理；手动压缩存在候选时不再返回无内容。真实发送请求符合预算，F002 待办、禁止条件和原文入口可用。同轮工具结果很大时按现有结果 ID 分页；不可分割的当前请求加必要状态已超限时如实说明，不循环压缩。

### REC-01 · 未知提交先查原操作，再决定是否续办

从 `mutations` 经 `runtime`、`turns` 到 `frontend/src/App.tsx` 传递原始错误码、操作号及恢复语义。将“核实结果”作为原页面的独立动作，复用 `verify_operation`，可更新核验标记，不得修改发票业务字段。只有操作归属、公司授权、原计划、修订和幂等指纹仍满足时才可继续同一操作。重读日志时与正在提交的事务互斥，`prepared` 仅说明已有准备记录；数据库不可达或提交仍在途时继续展示未知。已提交／无变化直接返回原回执，已拒绝展示原因，待用户确认仍要求确认。通用轮次重试不能隐式变成第二次写入。

**通过。** 在已建准备日志而业务尚未更新、提交完成但回读失败、响应丢失后重启三处注入故障。原轮均能按原号查验。增加双击核实／续办、原授权已撤销和旧计划已被取消的对照。数据库只保留同一业务动作，发票版本至多增加一次，用户最终看到的回执与数据库一致。

## 统一交付的判定

修复以上条目后，应同时得到正确业务值、正确可见范围、可重现的当前状态和可追溯的证据。独立验收人必须能用原页面切换用户／企业／Agent、上传 Excel／Word／文字型 PDF、完成多轮更正及恢复。固定同一模型与任务记录修复前后的实际输入、回复、工具结果和业务状态；程序探针与真实模型结果分别登记。在统一版本上通过对应门槛后，才能关闭原验收编号。
